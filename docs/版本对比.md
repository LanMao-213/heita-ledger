## 四、原版的三个硬伤(重写版已修)

1. **`PeriodChip` 零调用**:组件写好了没有任何页面用,活到 1.4.5。重写版改用统一 `SwipeFlip`,并用「扫源码数真实调用点」的测试钉住。
2. **借贷删不掉**:数据层有 `deleteDebt`,界面没有入口。重写版补了入口 + 二次确认 + 余额回滚。
3. **新账本没有子分类**:新建账本只灌一级分类。重写版修了,并有计数测试(支出 9/49、收入 6/24)。

## 五、决策记录(2026-10-21)

- **不替换,改为移植**:重写版功能少 20 条、视觉/滑动/记一笔三项手感均未达标、旧库迁移未做,所以**现阶段保留原版做日常记账**。
- **基线选 1.4.5 分支**:它比 `main` 领先 15 个提交、落后 0 个(可快进),已含 schema v8、期初余额、数据体检、明细懒加载、49 个测试文件。以 `main` 为基线等于把 1.4.5 的成果重做一遍。
- **视觉逐项定**:配色 → 卡片圆角/描边 → 字号阶梯 → 间距密度 → 图标 → 动效。第 1 项已定案(见交接说明)。
- **手感判断失误的复盘**:重写路子在「功能梳理」上是对的(98 条全部列清、ID 化),但在「手感」上错了——手感是五个版本真机磨出来的,写不出来,只能改出来。

## 六、为什么重写版不能直接覆盖安装

1. 包名相同(`com.heita.ledger`),装上会取代旧版;
2. 但重写版读不了旧库(schema v7/v8 → 新 v1),**没写迁移器**;
3. 覆盖后旧版又读不懂新库,**退不回去** → 用户唯一一本真实账目会处于「两边都不认」的状态。

要覆盖必须先完成:旧库检测 → 备份 → 独立连接读取 → 按规则转换 → 新库单事务写入 → 体检 → 报告。且要在备用机上用旧库副本验证笔数/月度合计/每账户余额逐项对齐后,才能装到主力机。
