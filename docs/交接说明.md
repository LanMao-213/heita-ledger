## 2. 第一次会遇到的问题

1. **你打的 release 包，装不到现在的手机上（大概率会撞上）**
   正式签名用的密钥 `android/app/release.jks` 和口令 `android/key.properties` **不在仓库里**
   （这是对的：签名文件泄露等于别人能以你的名义发版）。你 clone 下来没有这两个文件，
   `build.gradle.kts` 会**自动退回 debug 签名** —— 构建能成功，但签出来的包和手机上现有的
   1.3.0/1.4.0 签名不同，Android 不允许覆盖安装，只能卸载（= 本地账目清空）。
   两条路任选：
   - 找 NaiMao 要那两个文件，放到同一路径下（口令在 `key.properties` 里），之后就能覆盖升级；
   - 或者不碰正式包，只装 `com.heita.ledger.dev` 测试包（见第 4 节）。**它同样受签名影响**：
     手机上现有的 dev 包是正式签名的，你打的是 debug 签名，装之前得先
     `adb uninstall com.heita.ledger.dev`（dev 包里只有演示数据，删了不心疼）。

   > **本开发机现状（2026-10-20）**：两个文件已按上面第一条放好，`sha256` 与来源说明逐字符
   > 一致，签出来的包证书是 `CN=Heita Ledger`，SHA-256 `9f4670b1…de1799`。
   > **约定：从此所有包（含 dev 测试包）都用这把正式密钥签，不再退回 debug 签名**——
   > 换机器时第一件事就是把这两人文件放回来，否则又会出现「装不上」的老问题。

2. **`flutter test` 卡住不动**
   如果某个测试永远不结束，先看它有没有在 `testWidgets` 里直接 `await` 数据库。
   假时钟里 await 真实 I/O 会永久挂住，连超时都不触发。正确写法：

   ```dart
   await tester.runAsync(() async {
     await Store.i.boot();
     await _seedDemoData();
   });
   ```

3. **截图里中文变成方块**
   测试环境默认没有中文字形，`test/ui_shot_test.dart` 里会把系统的 `Deng.ttf` 当默认字体加载。
   换到 macOS 要改成 `PingFang.ttc` / `Hiragino Sans GB`，否则截图全是方块（不影响真机）。

4. **截图里图标变成方块**
   图标字体不会自动加载，测试里手动补了 `MaterialIcons-Regular.otf`
   （路径取 `FLUTTER_ROOT/bin/cache/artifacts/material_fonts/`）。SDK 装在别处就把 `FLUTTER_ROOT` 环境变量设上。

5. **多个测试文件并行跑，报「另一个程序正在使用此文件」**
   `flutter test` 是并行跑多个文件的。`Db.fileName` 可以改库名，
   各测试文件用各自的库（`test_template.db` / `test_shot.db`），别共用一个文件。

6. **改完表结构老数据没了**
   一定要升 `Db._version` 并写 `onUpgrade`（参考 1→2 那次：只 `ALTER TABLE ADD COLUMN`，不动数据）。

7. **`git clone` / `git push` 报证书错误（开着 Watt Toolkit 的 GitHub 加速时必现）**

   两种报错长得不一样，根因是同一个：

   ```
   fatal: unable to access '...': schannel: next InitializeSecurityContext failed:
   CRYPT_E_NO_REVOCATION_CHECK (0x80092012)
   fatal: unable to access '...': CONNECT tunnel failed, response 502
   ```

   不是 GitHub 的问题，也不是系统证书坏了。**Watt Toolkit（原 Steam++）的「GitHub 加速」会在本地
   起代理做 TLS 中间人**，动态签发一张 `CN=SteamTools Certificate / O=BeyondDimension` 的证书。
   这张自签根证书被装进了 Windows 根证书存储（所以不报「不受信任」），但它没有 CRL/OCSP 可查，
   Schannel 校验吊销状态时就抛 `0x80092012`。`gh`（Go 写的、不做吊销查询）不受影响，
   于是会出现「API 通、git 不通」这种很迷惑的现象 —— 2026-10-20 排查过一次，别再绕弯。

   查是不是被劫持，看颁发者就行：

   ```bash
   openssl s_client -connect github.com:443 -servername github.com </dev/null 2>/dev/null \
     | grep -E "^ *[0-9]+ s:|^ *i:"
   ```

   正常会看到 Sectigo / DigiCert / USERTrust 这类公共 CA；出现 `BeyondDimension` 就是中间人。

   **别用「本地代理端口还在不在」判断** —— 那个端口可能被别的进程占着。踩过一次：端口在监听，
   进程根本不是 Watt Toolkit，白查一轮。

   解法：关掉 GitHub 加速（或退出 Watt Toolkit），链立刻干净，`git` 一次就通，**不需要**
   `http.sslVerify=false` 这种降级。如果代理确实得开着，用
   `git config --global http.sslBackend schannel` + `git config --global http.schannelCheckRevoke false`
   —— 只跳过吊销查询，信任链仍然校验；注意不显式写 `sslBackend` 时那个开关**不生效**（实测）。

### 数据表

`ledger` `account` `category` `txn` `budget` `saving_goal` `recurring` `txn_template` `setting`

- 金额：`INTEGER`，单位**分**。1000 = ¥10.00。
- 日期：`TEXT`，`YYYY-MM-DD`；月份 `YYYY-MM`。
- `txn.category_id / account_id` 是软关联：分类被删时把它置空，不删交易。
- `txn_template.use_count / last_used_at` 只由 `Repo.touchTemplate` 改，不参与用户编辑。

### 改一处功能，通常要动的顺序

1. 表结构或字段 → `data/db.dart`（含 `onUpgrade`）+ `data/models.dart`
2. 查询/写入 → `data/repo.dart`
3. 内存状态要不要刷新 → `store.dart` 加个 `afterXxxChange`
4. 页面 → `pages/` 或 `widgets/`
5. 测试 → `test/`（界面改动记得跑截图自检）

### 真机走查：带演示数据的并排测试包（按需临时构建）

> **约定（2026-10-20 定）：对外只出正式包。** `apk/` 归档目录里只放 `com.heita.ledger`，
> dev 包是**临时诊断手段**，用完即弃，不归档、不发人。判断一个包是不是 dev 只看包名
> （`com.heita.ledger.dev`），**不能看「有没有演示数据」** —— 灌数据的前提是 `txn` 表为空，
> 库里有账时它一样没有假账，而正式包名配上 `HEITA_SEED=1` 也能打出带假账的包。
> 两条线职责：正式包 = 任何要留住数据的场景；dev 包 = 只在自己的测试机上。

手点几十笔去凑一份「有数据的界面」不现实，所以有一个专用构建：

```bash
flutter build apk --release --split-per-abi \
  -PappIdSuffix=.dev --dart-define=HEITA_SEED=1
```

- **包名变成 `com.heita.ledger.dev`**，和正式包共存，正式包里已有的账目一条不动。
  「需要加后缀」的根因是**签名**：`signingConfig` 挂在 `release` 这个 buildType 上，
  跟 `applicationId` 后缀没关系，所以 **dev 包用的是同一把正式密钥**。两者签名一致之后，
  dev 包之间可以直接覆盖升级，不用每次卸载。
  例外：2026-10-20 之前在本机打的 dev 包是 debug 签名，和现在的正式签名不同，
  那个包必须先 `adb uninstall com.heita.ledger.dev` 一次，之后就不再需要了。
- **首次启动自动灌一份演示数据**（`lib/dev/seed.dart`）：23 条流水覆盖两级分类与
  出发地/对象/名称三类详情、4 个账户、总预算与分类预算、2 个模板、3 笔借贷
  （未还 / 部分还 / 逾期 6 天 / 借入且计入预算）。库里已有流水时**不覆盖**。
- 想从头再来：`adb shell pm clear com.heita.ledger.dev` 再启动。
- 正式包不带 `HEITA_SEED`，这个分支会被编译器消掉，用户装的包里不存在演示数据。
- ⚠️ 开关必须写成 `--dart-define=HEITA_SEED=1` 并在代码里按字符串比较：
  `bool.fromEnvironment` 只认 `"true"`，传 `1` 会静默得到 false（踩过一次，包打出来了首页还是空的）。
- 改完种子跑 `flutter test test/seed_test.dart`：它断言了月度合计、借贷三种状态、
  **每条普通流水都必须匹配到分类**、**账户名不能重复**。后两条都是真机暴露后补的
  （第一版写了不存在的「外卖」分类，又把默认账户重复插了一遍）。

**为什么不能把 dev 包当正式包发**（2026-10-20 专门讨论过，结论是只留正式包）：

1. 两个包的 `application-label` **都是「黑塔消费日记」**，同时装着从桌面完全分不出来；
2. **（硬理由）** `lib/dev/seed.dart:23` 灌种子的条件只有「`txn` 表为空」，不认设备、不认首次安装。
   真实用户一清空数据、卸载重装、换机重装，启动就会凭空多出 23 条假账。账本混入假账就不可信了。
   正式包里 `kSeedDemoData` 是编译期 `const false`，那 317 行整段被编译器消掉，不存在这个风险；
3. `com.heita.ledger.dev` 一旦装到别人手机上，就再也收不到 `com.heita.ledger` 的更新；
   将来想「转正」只能卸载 + 备份恢复，历史升级链断掉。

## 5. 发版

### 5.1 一条命令链，从改号到发 Release

1. **改版本号，两处必须一致**：
   - `pubspec.yaml` 的 `version: 1.4.1+9`（`+` 后面是构建号，**每次发版 +1，只增不减**）
   - `lib/app.dart` 的 `kAppVersion`（「我的」页底部显示的就是它）

2. **跑检查**：`flutter analyze` 必须 0 issue，`flutter test` 必须全绿。
   界面有动过的，顺手看一眼 `build/visual/` 里的截图。

3. **出包**（**只出一套配色**——1.4.5 起「露露缇雅·泽金」与编译期开关 `HEITA` 已删除，
   不再需要出两个包；只打 arm64 用 `--target-platform android-arm64`，约 20 MB）：

   ```bash
   flutter build apk --release --split-per-abi
   ```

   产物在 `build/app/outputs/flutter-apk/`：
   `app-arm64-v8a-release.apk`（绝大多数手机）、`app-armeabi-v7a-release.apk`（老机型）、
   `app-x86_64-release.apk`（模拟器，不对外发）。

4. **验签**（不验就可能发出去一个 debug 签名的包，别人装不上）：

   ```bash
   java -jar $ANDROID_HOME/build-tools/<ver>/lib/apksigner.jar verify --print-certs \
     build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
   # 应看到 CN=Heita Ledger，而不是 CN=Android Debug
   ```

   再用 `aapt2 dump badging` 核对包名与版本号：

   ```bash
   $ANDROID_HOME/build-tools/<ver>/aapt2 dump badging \
     build/app/outputs/flutter-apk/app-arm64-v8a-release.apk | head -1
   # package: name='com.heita.ledger' versionCode='2009' versionName='1.4.1'
   ```

   > `versionCode` 不是 9，而是 **2009 / 1009** —— Flutter 分 ABI 打包时会给 arm64 加 2000、
   > armv7 加 1000 的偏移，这样同一构建号下 arm64 的包号永远更大。属于正常现象。

5. **改名归档**到仓库外的 `apk/`（这个目录在 `.gitignore` 里，不进版本库）：

   ```
   apk/heita-ledger-1.4.1-arm64.apk    ← app-arm64-v8a-release.apk
   apk/heita-ledger-1.4.1-armv7.apk    ← app-armeabi-v7a-release.apk
   ```

6. **提交 + 打标签 + 推**：

   ```bash
   git add -A && git commit -m "chore(release): 1.4.1+9"
   git tag -a v1.4.1 -m "1.4.1+9"
   git push origin main && git push origin v1.4.1
   ```

## 10. 1.3.0 借贷往来（2026-10-19）

设计全文在 `docs/借贷往来-设计.md`（含六项口径的确认记录）。这里只记落地时最容易踩的几条。

### 数据模型

- **迁移 v6→v7**：新建 `debt` 表，`txn` 加 `debt_id`。只建表加列，不动任何一行老交易。
  老库没有 `txn` 表时（升级测试造的那种）迁移会跳过加列，真实库不会缺这张表。
- `debt`：方向（`out` 借出 / `in` 借入）、对方、本金、账户、日期、应还日、`count_in_budget`、`closed_at`、备注。
- **已还 / 剩余不落库**，每次按 `txn` 流水实时算。这是整套功能最核心的数字，存冗余必然和流水对不上。
- **不扩 `TxnType` 枚举**：借贷流水在库里仍是 `expense` / `income`，靠 `debt_id` 区分。
  扩枚举要改遍所有按类型分支的地方（明细分组、筛选、Excel 类型列、统计、周期归集、备份），漏一处就有一个数字错。

### 口径（改统计的先看这里）

「借贷不算收支」收敛到 6 个点，**新增聚合查询必须复用这些常量，不要另写 WHERE**：

| 位置 | 做法 |
| --- | --- |
| `Repo._expSumSql` / `_incSumSql` | 借贷一律算 0（月度合计、筛选合计共用） |
| 分类聚合（饼图/排行） | `WHERE ... debt_id IS NULL` |
| 每日趋势 | 同上 |
| 预算已用 | 子查询加 `debt_id IS NULL` |
| `sumBySide` | 内存里按 `debtId` 跳过 |

净资产 = 账户余额 + 应收 − 应付（`Store.netWorthWithDebtCents`，由 `receivableCents` / `payableCents` 组合）。
只减余额不加应收，借出 5000 会看起来像钱丢了。

### 借入与预算的关系（2026-10-20 补，用户拍过口径）

`debt.count_in_budget = 1` 的**本期**借入，会让本期可用额度变大：

```
可用额度 budgetAvailableCents = 总预算额度 + borrowedInBudgetCents
```

- **额度本身不改**：`totalBudgetCents` 永远是你设的那个数（6,000），借入只体现为「可用」，
  下期不再借就自动还原，不需要手动改回去。
- **显示**：计划页与明细页的预算卡大数字直接显示**额度 + 借入**（设 6,000、借入 3,000 → 9,000），
  下面小字「含借入 3,000（额度 6,000）」。这一条按用户原话改过一次：早先是「大数字仍 6,000、
  另起一行写含借入」，看起来像预算没变。
- **一致性**：已用百分比、剩余金额、每天可花三处全部走 `budgetAvailableCents`，
  不要单独拿 `totalBudgetCents` 去算，否则会出现「进度条 56% 但剩余对不上」。
- **借出恒不计入**：`Repo.createDebt` 兜底把 `count_in_budget` 改成 0，不信调用方。
- **只算本期**：上期借的钱不抬这一期额度，见 `test/budget_borrowed_test.dart` 第 4 条。

### 交互

- 记一笔顶部四段：支出 / 收入 / 借出 / 借入。借贷模式隐藏分类与详情，改填「对方（必填）」「应还日」，
  借入多一个「计入预算」开关。**模式只存在于录入面板，不进数据库。**
- 明细里借贷行是「借出 · 张三」+ 中性灰 + 「应还 11-30」，点开进往来详情（不是普通编辑面板）。
- 往来页：计划页顶部摘要卡 → 台账 → 详情 → 记还款（默认剩余、超额在面板和 `Repo` 各拦一次）。

### 周期条的手势（2026-10-20 起）

区间文案从「10-01 → 10-31」改成「10-01 **至** 10-31」，左右箭头去掉，翻页全靠手势：

| 手势 | 行为 |
| --- | --- |
| 左右轻扫 | 翻上/下一期（或上/下一月，统计页按月看时） |
| 双击 | 回到今天所在的期（按月看时回本月） |
| 单击 | 弹日历挑日期（保持原样） |

实现都在 `lib/widgets/common.dart` 的 `_SwipeFlip`：速度和位移双阈值（260 px/s 或 48 px），
手指抖一下不翻页。**单击要等 300ms 的双击判定窗口**（`kDoubleTapTimeout`）才触发日历 ——
这是同一块区域挂「单击 + 双击」的固有成本，不是卡顿。

⚠️ 双击在自动化里验过（`test/period_swipe_test.dart`，间隔 60ms），但 `adb shell input tap`
两次之间隔 300ms 以上（每次都要拉起一个 JVM），所以真机自动化造不出双击，只能手点。

### 已知取舍

- 还款只能新增、不能改：记错金额就删掉这条还款流水重记，避免动本金。
- 往来按人汇总在 `lib/data/debt_grouping.dart`（纯函数，可直接单测）：同一个人的几笔合并成
  一行净额，既有借出又有借入时净额相抵、副行同时标出两边金额；已结清的不进汇总。
  排序是「逾期最久 → 到期最近 → 净额最大 → 姓名」，保证同一份数据每次打开顺序一致。

### 环境相关的几个硬事实

- `adb` **不在 PATH**：`C:/dev/android-sdk/platform-tools/adb.exe`；`flutter` 在 `C:/dev/flutter/bin`。
- 跑测试要去掉代理变量，否则 `flutter_tester` 的本地回环会被劫持、测试进程起不来：
  `env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY=localhost,127.0.0.1 flutter test`
- 推 GitHub 如果报 `CONNECT tunnel failed` 或 `CRYPT_E_NO_REVOCATION_CHECK`，
  根因和查法见[第 2 节第 7 条](#2-第一次会遇到的问题)：八成是 Watt Toolkit 的 GitHub 加速在做中间人。
  修好之前别用 `curl` 探活判断通不通 —— 实测过 curl 返回 000 但 git 一次就通的情况。
- **代理端口每次会话都可能变**（见过 `17729` → `27002` → `53533`）。排查网络前先读环境变量，
  **别把端口写死**：

  ```bash
  echo "$https_proxy"                 # 当前真实端口
  curl --ssl-no-revoke -x "$https_proxy" https://api.github.com/rate_limit
  ```

  写死端口时所有域名一律返回 `000`，看起来和「网全断了」一模一样 —— 2026-10-28 就这么误判过一次，
  实际是端口已换、旧端口没人监听。
- **必须用 `curl` 打 GitHub API 时（查 CI、建 Release）加 `--ssl-no-revoke`**。
  它只跳过**吊销状态查询**，证书链与域名照常校验；不加就是 `exit 35` +
  `schannel: next InitializeSecurityContext failed: CRYPT_E_NO_REVOCATION_CHECK`。
  同一个端口下 `codeload.github.com` 可能通而 `api.github.com` 不通（前者证书链的 CRL 端点可达），
  所以「有的域名通、有的不通」也不能证明网络是好的。
  `git` 不受影响：它用 `GIT_SSL_NO_VERIFY=1` 就绕过了这条检查。
- **`git push` 报 `Empty reply from server` / `Recv failure: Connection was reset`，
  但 `ls-remote` 又正常** —— 这是「能读不能写」的典型表现，不是仓库坏了、也不是权限问题。
  读是小请求，push 要上传 pack，中间设备往往只掐上传那一段。带 `git -c http.version=HTTP/1.1` 重试
  基本一次就过（实测 2026-10-20）：

  ```bash
  env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
    git -c http.version=HTTP/1.1 -c http.postBuffer=524288000 push origin main
  ```

  判断顺序是：先 `git ls-remote origin -h refs/heads/main`，**通**就说明网络和凭据都没问题，
  直接在 push 上加 HTTP/1.1，别去折腾 SSH key 或重新登录。
- `gh` 不在 PATH，在 `C:/Users/<用户>/.workbuddy/binaries/gh/bin/gh.exe`；
  它已登录（token 带 `repo` scope），建 Release 直接用，同样要剥代理变量。
- **推 `.github/workflows/` 需要 token 带 `workflow` scope**，缺了不会只拒那个文件，
  而是**整次 push 被拒**：
  `refusing to allow an OAuth App to create or update workflow ... without workflow scope`。
  1.4.4 就是这么少了一个 CI。遇到先 `gh auth status` 看 scopes，
  再 `gh auth refresh -h github.com -s workflow` 补上。
- 截图自检（`test/ui_shot_test.dart`）有两个坑：整棵树被换掉时必须自己套一层
  `RepaintBoundary(key: _shotKey)`，否则 `_shot()` 空指针；页面 `initState` 里要读
  文件的，**建树也得放进 `runAsync`**，假时钟里那个 Future 永远回不来，会卡在 loading。

## 12. 单套「纸墨」色板

1.4.5+13 把配色从「编译期双套」收成**一套**，方向是**纸墨**：纸白底 + 暖灰墨字，
不引入装饰色。1.4.5 那套「露露缇雅·泽金」（天青底 + 暖白卡 + 绯红超支 + 薰衣草次级）
**已整体删除** —— `--dart-define=HEITA=1` 不再有任何作用，`kHeita` 这个开关也不存在了。

### 为什么删掉双套

双套的实际代价：每个颜色 token 维护两个值、每条界面改动验两遍、CI 里测试跑两遍，
而两个包的数据还不互通（`com.heita.ledger.heita` 是一本独立空账，装上去等于重新开始）。
实际用的人只会装一个包。单套之后 `tokens.dart` 每个 token 就是一个 `static const` 字面量，
`test/theme_palette_test.dart` 一组断言就能把整套值钉死。

**仍然全部是 `static const`**：全仓库 457 处 `C.xxx` 都写在 `const TextStyle(...)` /
`const BoxDecoration(...)` 里，颜色一旦变成运行时 getter，这些 const 构造全要拆掉。
单套色板也没有运行时可变的必要，所以这条不放松。

图表色阶 `kChart` 是**暖灰十档**（`#1C1A17` → `#E4DED2`），越靠前越主要；
相邻两档靠明度分，不靠色相 —— 饼图颜色只表示「不同」，不表示「是什么」。

### 四条层级约束（`test/design/tokens_contrast_test.dart` 逐条断言）

1. `bg2` 比 `cardBg` 深**且**比 `bg` 深 —— 键帽必须沉下去；
   反过来 `cardBg` 要比 `bg` 亮，这是「卡浮起来」的唯一依据（投影只有 4%，撑不起层级）。
2. `heroBg` 比 `bg` 深，且与 `cardBg` 不同 —— 否则「汇总区压下、记录卡浮上」的层级就没了。
3. `line` 对 `cardBg` 的对比在 **1.05–1.45** 之间 —— 看得见，但不抢文字。
4. `ink` 对 `bg` ≥ 7:1；`ink2`、`ink3`、`over` 对 `bg` ≥ 4.5:1。
   其中 `ink3` 是这一轮修掉的既有缺陷：旧色板 `#9AA0A8` 在白底上只有 2.6:1，
   而 12.5px 的 `caption` 一直在用。

### 改配色时守住的两条

1. **别写死颜色字面量**。会露馅的地方全是「直接写的 `Color(0xFF...)`」——
   新颜色一律先进 `tokens.dart` 再引用。
2. **改完先跑 `flutter test test/design/tokens_contrast_test.dart`**。
   它只验「值之间的关系」（对比度与层级），换色板不用改它；破坏了可读性会立刻红。
   `test/theme_palette_test.dart` 钉的是「当前这套值」，换色板时两者一起改。

### 构建

```bash
# 只有一套配色，正常打包即可，没有 dart-define
flutter build apk --release --target-platform android-arm64
```

`android/app/build.gradle.kts` 里的 `-PappIdSuffix=.dev` **保留**：那是通用的
「打一个能与正式包并存安装的测试包」能力（`com.heita.ledger.dev`），与配色无关。
`--dart-define=HEITA_SEED=1` 演示数据开关也保留，用法见[第 3 节](#3-演示数据heita_seed)。
