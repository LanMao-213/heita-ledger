# UI 柔和化改造（1.5.0）

> 起因：用户反馈「目前的设计有一点僵硬和不和谐」。
> 目标：保留全部功能，重做视觉系统，让色彩层级立起来、让界面不再是硬切。

## 一、诊断：僵硬到底出在哪

不是颜色不好看，是**层级立不起来**。逐条实测（不是凭感觉）：

| # | 现象 | 实测数据 | 后果 |
|---|---|---|---|
| 1 | 底与卡几乎同色 | `bg #FBFAF7` 与 `cardBg #FFFFFF` 只差 **1.06:1** | 卡片浮不起来，边界只能靠描边撑 |
| 2 | 而描边又几乎看不见 | `C.line` 对白卡 **1.29:1** | 描边形同虚设，整屏退化成「被细线切开的白板」 |
| 3 | 全库只有 1 张卡有投影 | `BoxShadow` 仅 3 处声明，其中 2 处是 FAB | 界面是纯平面的，没有纵深 |
| 4 | **几乎没有动效** | `AnimationController` **0**、`AnimatedList` **0**、`Hero` **0**；翻期、Tab 选中、删除、展开、大数字变化全是 **0ms 硬切** | **僵硬的最大来源** |
| 5 | 层级差不足 1px | 字号实测 14.5 / 13.5 / 12.5 三档只差 1px | 一行里读不出主次，糊成一片 |
| 6 | 三套卡片三套边距 | SectionCard `20/8`、日卡 `16/8`、概览卡 `16/12/4` | 屏幕被切成一堆对不齐的矩形 |
| 7 | 82 个图标零粗细分层 | 全部 1.5 线宽，尺寸 15/16/17/18/19/20/22/40 随意指定 | 图标没有视觉重量差 |

结论：**问题不在色相，在「面、线、动」这三件事的用法**。所以这一轮没有换配色方向，仍然走「纸墨」，只是把它重做成一个能立得住的系统。

## 二、新的设计系统

### 2.1 用「面」分界，不用「线」分界

这是本轮的核心原则。面的层级（同暖色相、明度递进）：

| 面 | 值 | 相对关系 |
|---|---|---|
| `cardBg` 卡片（浮起） | `#FFFFFF` | 对 `bg` **1.12:1**（旧值 1.06:1） |
| `bg` 页面底 | `#F5F2EA` | — |
| `bg3` 更弱的面 | `#EDE8DF` | — |
| `heroBg` 概览卡（压下） | `#ECE7DE` | 对 `bg` **1.10:1** |
| `bg2` 键帽 / 次级面 | `#E4DED0` | 对 `bg` **1.20:1** |

`bg` 从 `#FBFAF7` 压深到 `#F5F2EA`，是整套改动的**枢纽**：只有底足够深，白卡才第一次真的「浮」起来，描边才能退居次要。

### 2.2 投影代替描边（`E`）

三档，共同点是「大 blur + 小 offset + 低透明」——模糊半径远大于位移，影子是**贴着卡片晕开**，而不是在卡片后面拖一条黑边。用墨色而非纯黑投影，免得把暖调画面压灰。

| 档 | blur | 位移 | 墨 |
|---|---|---|---|
| `E.low` 卡片 | 10 | (0,2) | 5% |
| `E.mid` 抽屉/对话框 | 20 | (0,6) | 7% |
| `E.high` FAB | 28 | (0,10) | 10% |

### 2.3 连续圆角（`R` + `Shape`）

iOS 的圆角不是圆弧，是**超椭圆（squircle）**：曲率在角上连续变化，视觉上比 `RoundedRectangleBorder` 更软更紧。Flutter 3.13+ 原生提供 `RoundedSuperellipseBorder`，本项目 3.47.7 可用。

圆角整体放大一档：`8 / 12 / 16 / 20 / 24 / 30`（旧 `9 / 13 / 16 / 20`）。圆角越大，矩形的「盒子感」越弱。

```dart
decoration: ShapeDecoration(
  color: C.cardBg,
  shadows: E.low,
  shape: Shape.squircle(R.card),
)
```

### 2.4 字号拉开层级（`T`）

相邻档位从 1px 差拉到 2–3px：

| 用途 | 旧 | 新 |
|---|---|---|
| 大数字 `hero` | 34 | 34（+ 等宽数字） |
| 标题 `title` | 20 | 22 |
| 分组 `section` | 15 | 16 |
| 正文 `body` | 14.5 | **15** |
| 次要 `body2` | 13.5 | **13** |
| 辅助 `caption` | 12.5 | **12** |
| 小标签 `overline` | — | 11（新增） |
| 金额 `amount` | 16 | **17** |

### 2.5 动效（`M`，新增）

上一版全库只有 7 处隐式动画。现在：

| 档 | 时长 | 用在哪 |
|---|---|---|
| `M.tap` | 120ms | 按下 / 抬手 |
| `M.fast` | 180ms | 行内状态变化（Tab 选中、勾选） |
| `M.base` | 260ms | 展开收起、数字滚动、列表进出场 |
| `M.slow` | 380ms | 抽屉、弹层 |
| `M.page` | 420ms | 页面转场 |

曲线：`standard`（easeOutCubic）、`emphasized`、`ios`、`spring`。

页面转场从安卓默认的上下淡入换成 `CupertinoPageTransitionsBuilder`（右进右出 + 边缘跟手返回）——这是「苹果感」最容易被感知的一条。

## 三、改了什么

### 3.1 底座（`lib/design/tokens.dart`）
色板重做、`E`/`Shape`/`M` 新增、`R` 放大、`T` 拉开、`S` 补 32/40；主题里 `cardTheme` / `dialogTheme` / `bottomSheetTheme` 统一走连续圆角 + 无描边，分隔线压到 1px，页面转场换 iOS。

### 3.2 基础组件（`lib/widgets/common.dart`）
- `SectionCard`：「白底 + 1px 描边」→ 「白面 + `E.low` + 连续圆角」；新增 `sunken` 开关，让只用了 1 次的 `heroBg` 真正落地成「压下去」那一档。左右边距从 20 收到 16，与明细日卡对齐。
- `SectionTitle`：左右对齐到 16，上下 20/10 给分组一个区块停顿。
- `SegTabs`：滑块改为「白面 + 柔投影 + squircle」，文字颜色走 `AnimatedDefaultTextStyle`（原来底色滑过去了、字色还是硬切）。

### 3.3 动效（`lib/design/motion.dart`，新增）
`AnimatedMoney` / `FadeSlideIn` / `Pressable` / `AnimatedExpand` 四个通用组件，接入 5 处：
1. 底部 Tab 选中态 —— 图标 `AnimatedScale`（1.0 / 0.92）+ 文字渐变
2. 概览卡大数字 —— 新值从下方 8px 滑入、旧值向上淡出
3. 翻期 —— `jumpTo` → `animateTo`，内容淡入
4. 记一笔详情区展开 —— `if (open)` 裸切换 → `AnimatedExpand`
5. 交易行进场 —— `FadeSlideIn`

### 3.4 描边清理（第二轮）
9 处 `Border.all` 按语义分成两类处理：
- **A 类（卡片边界）4 处** → 删描边，改 `ShapeDecoration` + `E.low` + squircle：往来人卡、单笔往来卡、明细日卡、概览卡
- **B 类（真的要切断）5 处** → 保留描边，圆角走令牌：账单日格子、分段控件、账户芯片、两处取消按钮

明细日卡原来是「描边 + 投影 + 白底」三层叠加，紧邻的概览卡又是另一套，同屏两套卡片语法、边界发糊——这一处已统一。

顺带把 17 处硬编码圆角换成 `R.*` 令牌；5 处按例外保留（进度条的高度一半胶囊、柱状图柱顶等）。

### 3.5 字号收编（第三轮）
59 处硬编码 `fontSize` 分两批收进 `T` 令牌（`37911db` 50 处、`65d1c91` 剩余 5 处），
现在全库裸 `fontSize` 为 0。

### 3.6 分隔线改物理 1 像素（第三轮）
新增 `lib/design/hairline.dart` 的 `hairlineOf(context)` = `1 / devicePixelRatio`，
**27/27 处 `Divider`** 全部只改 `thickness`（`height`/`color`/`indent`/`endIndent` 不动），
外加 2 处纵向 1px 线。3x 屏上从 3 物理像素降回 1。

### 3.7 留白节奏重排（第三轮）

**① 分组节奏：从「均匀」改成「有层级」。** `SectionTitle` 上下 padding 是和
`SectionCard` 的外边距（上下 8）相加才等于屏幕上的实际距离的：

| 关系 | 旧值 | 新值 |
|---|---|---|
| 标题 → 它领导的卡 | 12+8 = **20** | 4+8 = **12** |
| 组内 卡 ↔ 卡 | 8+8 = **16** | **16**（不变） |
| 卡 → 下一个标题（组间距） | 8+20 = **28** | 8+24 = **32** |

旧值的问题：标题离自己那一组（20）比组内两项之间（16）还远，标题读起来
「不属于」下面那组；组间距只比项间距大 1.75 倍，一屏全是差不多大的间距。
新的 **12 < 16 < 32** 是刻意排的递进——标题必须比组内间距更贴住它领导的组，
用户才读得出归属；组间距拉到项间距 2 倍，粗细两种停顿才分得开。

`templates_page` 是表单页，标题下面跟的是 `TextField`/`SegTabs`/`Wrap`，没有
`SectionCard` 的 8 可加、只剩 4 太挤，在那 6 个标题后各补一个 `SizedBox(height: S.xs)`
变成 8。表单页 8、卡片页 12，不动 `SectionTitle` 这个全局组件。

**② 卡片内边距归一到三档**（写进 `SectionCard` 类注释）：
内容卡 `all(S.lg)`=16（默认，不覆盖）/ 列表卡 `symmetric(vertical: S.sm)`=上下 8 左右 0，
行自己补 `horizontal: S.lg` / 空态卡 `symmetric(horizontal: S.lg, vertical: S.xxl)`=16/24。
旧代码三套卡三套边距（20/8、16/8、16/12/4），卡与卡左右对不齐。改了 20 处调用点。

**③ 横向内容列统一到 16**：24 处横向 `S.xl`(20) → `S.lg`(16)，纵向一律不动。
残留的 20 会和基准 16 在同一屏错开 4px。保留两处刻意的例外并加注释：
`detail_page` 筛选栏的非对称布局、`filter_sheet` 子分类那排「子级再往里缩一档」。

**保留不动的**：拖拽手柄 6、开关轨道内缩 3、dense 输入框 9/13、日卡行纵向 11、
角标 5/1、分隔点 2——这些决定的是控件自身高度，不参与页面节奏，已逐个加注释。
