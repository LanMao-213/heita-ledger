## 二、验证包怎么来的（不覆盖用户数据）

仓库不含 `android/key.properties` 与 `release.jks`（正式密钥从不进版本库），
因此**无法产出能覆盖安装到 1.4.6 之上的包**——签名不同，只能卸载，而卸载会清空真实账目。

采用的方案是仓库自带的并存安装机制：

```bash
flutter build apk --release --target-platform android-arm64 -PappIdSuffix=.dev
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

产出 `com.heita.ledger.dev`（1.5.0+24，19.6 MB），与 `com.heita.ledger` **并存**，
原包与账目一条未动。

### 用仓库自带工具做的出包校验

`python tools/verify_apk.py`（需先设 `ANDROID_HOME`）：

| 检查项 | 结果 |
|---|---|
| 包名 | FAIL — 实为 `com.heita.ledger.dev`（**预期**，正是并存方案要的） |
| 版本号 | OK — 1.5.0+24，与 pubspec 一致 |
| kAppVersion | OK — 1.5.0，与 pubspec 一致 |
| 签名 | FAIL — debug 签名（**预期**，本机无正式密钥） |
| 权限 | **OK — 零联网权限** |
| 图标 | OK — 1 个图标资源 |
| ABI | OK — arm64-v8a |

两条 FAIL 都是这个验证包**按设计本该有的属性**，不是缺陷；该包不用于分发。

## 三、四项验收结果

### 1. 冷启动：无品牌启动页 —— 通过（附带一个已知取舍被实测复现）

做法：`am force-stop` 后 `am start`，连续 4 帧抓屏。

| 帧 | 文件大小 | 内容 |
|---|---|---|
| 第 1 帧 | 38 KB | **纯浅色底，无任何品牌标志** |
| 第 2–4 帧 | 147 KB | 直接进入主界面 |

证据：`build/device/cold_1.png`（浅底空屏）、`build/device/cold_2.png`（主界面）。

**同时实测复现了 CHANGELOG 记录的已知取舍**：出厂皮肤是「黑塔·永夜」（深色），
而原生启动窗口取默认浅色 `#F3F4F7` —— 用户会看到一次「浅 → 深」跳变。
这是文档里写明的取舍（要消掉需 `MainActivity` 读 SharedPreferences 再 `setBackgroundDrawable`，
本轮未做），不是新缺陷，但**现在有了实拍证据**。

### 2. 金额输入：`1` 后按小数点不变 `0` —— 通过

用 `uiautomator dump` 取键位坐标，按真实按键逐步点击并逐帧抓屏：

| 操作 | 金额区显示 |
|---|---|
| C 清空 | `0` |
| 按 `1` | `1` |
| 按 `.` | **`1.`** ← 旧版在这里变回 `0` |
| 按 `5` | `1.50` |
| 按 `3` | `1.53` |

证据：`build/device/amount_seq.png`（五帧纵向拼接）。

> 说明：输入小数位后显示固定两位（`1.50`），是显示规则，不是缺陷。

### 3. 出行不细分也有地址入口 —— 通过

滚动分类双轮盘选中「出行 / 不细分」→ 确定：

- 面板出现「＋ 添加详情」
- 展开后字段为：**出发地**（占位「从哪出发」）、**目的地**（占位「到哪去」）

证据：`build/device/travel_detail.png`。

旧版此处整块不渲染（`kSubFieldSpecs` 只按子分类名登记，一级分类查不到）。

### 4. 备注框与键盘的位置 —— 通过

先收起详情，再点备注唤起系统键盘，然后按像素逐行扫描定位边界：

| 测点 | 实测 |
|---|---|
| 键盘上沿 | y = **1782**（像素 213,215,221 起始行） |
| 面板底边 | y = **1782** |

**面板底边与键盘上沿完全贴合，间隙 0px**（旧版此处空 101.6dp）。

备注框底边在 y≈1417，其下方是「今天 / 现金」按钮行与「添加详情」行，
所以备注框到键盘之间隔着这两行——**属正常布局，不是留白缺陷**。

证据：`build/device/note_final.png`。

## 四、结论与遗留

**四项全过。** 1.5.0 从「能编译、563 条测试全绿」升级为「真机上用起来对」。

遗留（本轮不处理，已登记）：

1. **深色皮肤冷启动「浅→深」跳变** —— 实拍确认存在，属文档记录的取舍。修法明确（原生读皮肤再设窗口底色），代价是新增一条原生↔Dart 同步链路。
2. **验证包是 debug 签名** —— 无法分发。要给真实用户升级，必须拿到 `release.jks` + `key.properties`，否则老用户只能卸载重装（账目清空）。
3. **手机上的 `.dev` 包是临时验证物**，验收完成后应卸载：
   `adb shell pm uninstall com.heita.ledger.dev`（只删 `.dev`，`com.heita.ledger` 与账目不受影响）。
4. **构建路径含用户名** —— 本次验证包在 `C:/Users/<用户名>/...` 下构建，`libapp.so` 会嵌入该绝对路径。仅本地验证无碍，但**正式发版必须按 README 在无用户名路径下构建**。

## 五、可复现命令

```bash
# 0. 环境
export ANDROID_HOME="C:/dev/android-sdk"
export MSYS_NO_PATHCONV=1          # Git Bash 必需，否则 /sdcard/ 会被转成 Windows 路径
ADB="$ANDROID_HOME/platform-tools/adb.exe"

# 1. 设备确认
"$ADB" devices -l

# 2. 基线（干净克隆应为 0 issue / 563 条全绿）
flutter analyze --fatal-infos
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy NO_PROXY=localhost,127.0.0.1 flutter test

# 3. 出并存验证包
flutter build apk --release --target-platform android-arm64 -PappIdSuffix=.dev
python tools/verify_apk.py build/app/outputs/flutter-apk/app-release.apk

# 4. 安装并启动
"$ADB" install -r build/app/outputs/flutter-apk/app-release.apk
"$ADB" shell am force-stop com.heita.ledger.dev
"$ADB" shell am start -n com.heita.ledger.dev/com.heita.ledger.MainActivity

# 5. 取界面坐标（点击自动化用）
"$ADB" shell uiautomator dump /sdcard/ui.xml
"$ADB" pull /sdcard/ui.xml build/device/ui.xml

# 6. 验收完清理
"$ADB" shell pm uninstall com.heita.ledger.dev
```
