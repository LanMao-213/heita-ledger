## 2. 项目结构

完整版见 `docs/代码地图.md`，这里只给骨架：

```
lib/
  design/        颜色 / 字号 / 间距 / 圆角 token、自绘图标、动效
  data/          纯 Dart，不 import Flutter
    models.dart         库入口（import + part）
    models/             fmt / ledger / txn / plan / stats
    db.dart             建表、索引、迁移链
    command.dart        Command + WriteGateway（一次写入一个事务）
    repo.dart           Repo 门面（只有转发）
    repo/               settings ledger account category txn debt budget
                        goal recurring template backup commands
    repo_stats.dart     读侧聚合
    bill_csv.dart       BillCsv 门面
    bill/               models format decode parse dedupe
    backup_service.dart backup_compat.dart integrity.dart cycle.dart
  store.dart      Store 类体：字段（全私有）、启动与加载、after* 重算、派生 getter
  store/          state.dart（只读投影）actions.dart（用例方法）views.dart（分组视图）
  pages/          4 个主 Tab + 8 个二级页
  widgets/        记账面板、图表、键盘、选择器、公共件
test/             525 条；support/ 下有 schema 比对与写入等待工具
tools/            隐私扫描、出包校验、图标生成、截图对拍
docs/             代码地图、写入口清单、各类设计文档、历史交接说明
```

**依赖方向是单向的**：`design ← data ← store ← pages/widgets`。
`lib/data` **不允许** import Flutter 或 `design/`（有测试守着），这是它能脱离 UI 单测的前提。

## 3. 运行方式

### 环境

- Flutter **3.47.7**（与 CI 固定版本一致；升版本时要同步改 `.github/workflows/ci.yml`）
- Dart 随 Flutter 安装，无额外 SDK
- 只跑测试不需要 Android SDK

### ⚠️ 跑任何 flutter 命令都要先剥代理

这台机器上代理会拦住 Dart 的本地回环，不剥就会挂在 `pub get` 或测试启动：

```bash
cd <repo>
env -u HTTP_PROXY -u HTTPS_PROXY -u ALL_PROXY \
    NO_PROXY=localhost,127.0.0.1 \
    PUB_CACHE=C:/Users/<你>/AppData/Local/Pub/Cache \
    flutter test
```

（`tools/pub_get.sh` 里有同样的写法，可以直接用。）

### 常用命令

```bash
flutter analyze --fatal-infos      # 必须 0 issue（CI 门禁）
flutter test                       # 525 条
flutter test --dart-define=HEITA=1 # 备用配色分支，CI 第二条也跑

flutter test test/ui_layout_regression_test.dart   # 布局回归网（快）
flutter test test/architecture_test.dart           # 结构护栏（快）
python tools/privacy_scan.py                       # 提交前隐私扫描
python tools/privacy_scan.py --history             # 连历史一起扫
```

### 出包

签名配置（`android/key.properties` + `release.jks`）只在本地有。**构建目录路径里
不能含用户名**（既有硬约束），否则出包工具会拒绝。详见 `docs/交接说明.md` 第 5 节。

### 改 UI 前后怎么确认「没变」

```bash
flutter test test/ui_shot_test.dart --dart-define=SHOT_DIR=build/visual/base
# 改代码（重构/拆 widget），不改行为
flutter test test/ui_shot_test.dart --dart-define=SHOT_DIR=build/visual/after
python tools/visual_diff.py build/visual/base build/visual/after \
       --exclude shot_24_safety
# 期望：exit 0
```

这套东西是**一次性的**，不是 golden 基线：截图在 `build/visual/`（已被 gitignore），
用完删掉即可。为什么不做 `matchesGoldenFile` 见 `CHANGELOG.md` 结尾的说明。

> 一个容易误会的地方：`ui_shot_test.dart` 在 CI 上**不会失败**。它找不到
> `C:\Windows\Fonts` 时只打印「文字会显示为方块」的警告就返回，截图也不做断言。
> 所以 CI 证明的是「页面能渲染、不溢出」，**不证明视觉正确** ——
> 视觉核对只能在本机用上面的对拍流程做。

## 4. 后续注意事项（踩过的坑，别再踩）

1. **门面只许转发**。往 `lib/data/repo.dart` 或 `bill_csv.dart` 里加方法体会让
   `test/architecture_test.dart` 变红 —— 这是故意的：这两个文件曾经各有一千八百行。
2. **不要给 `Store` 加公开可变字段**。页面一旦能直接改投影，投影就会和库分叉，
   而且分叉后所有合计/结余都是错的且看不出原因。要加只读投影，写进 `store/state.dart`。
3. **写库必须走 `Store` 的用例方法**（`store/actions.dart`），它会顺带刷新投影。
   只读查询可以直接调 `Repo.listXxx`。规矩详见 `docs/写入口清单.md` 第五节。
4. **`part` 文件漏写就说不上话**：`models/` 或 `repo/` 下新增文件后，必须同时在
   宿主文件里加 `part` 指令，否则它**不参与编译且 `analyze` 不报**。护栏第 5 条会查这个。
5. **`shot_24_safety.png` 天生不确定**（差 45~90 像素，位于页面上快照的体积/时间数字）。
   对拍时 `--exclude shot_24_safety`。根治办法：让该用例读固定 fixture，而不是现写快照。
6. **改 schema 之前先看 `test/schema_equivalence_test.dart`**。它比对「全新装库」与
   「老库升级」的逐表逐列与索引 —— 漏一列就是启动即崩，而这个测试是本轮才建好的，
   v9 迁移必须复用它。
7. **GBK 仍然不支持**（Dart 核心库没有 GBK 编解码，项目约定不新增依赖）。
   现在遇到 GBK 账单是**明确报错并给操作指引**，这是有意为之：硬解会把乱码写进账本，
   而乱码事后极难挑出来。
8. **隐私红线**：仓库公开。真实账目（`*.db` / `*.xlsx` / 备份 JSON）、本机绝对路径、
   签名文件都不能进版本库 —— `.gitignore` 已挡住，但**拷文件进来时别顺手 `-f`**。
   提交前跑 `python tools/privacy_scan.py`。
