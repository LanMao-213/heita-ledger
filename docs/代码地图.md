# 代码地图（2026-10 结构整理后）

> 「某个东西在哪」比「它怎么实现」更常被问。这份文件只回答前者，
> 并且只写**结构约束**——违反了会有测试变红（`test/architecture_test.dart`）。

## 一、分层的方向

```
design  ←  ┐
           ├─ pages / widgets
data    ←  ┘        ↑
  ↑                 │
store ──────────────┘
```

- `lib/data` **不 import Flutter、不 import design**（纯 Dart，可脱离 UI 单测）
- `lib/design` 不 import 任何业务层
- `lib/store` 依赖 `data`，是唯一持有可变状态的地方
- `lib/pages`、`lib/widgets`：只读 `store` 的投影；写操作一律调 `Store` 的方法

违反第一条或第三条 → `architecture_test.dart` 直接报文件名。

### `Repo` 的两个规矩

1. **要改实现，去 `data/repo/<域>.dart`**，不要在 `repo.dart` 里写方法体 ——
   门面只允许一行转发，写了实现测试会红。
2. **`Repo` 里不放业务编排**。它的每个方法对应「一次数据库对话」；
   跨多次写入的语义（建借贷 = 往来 + 本金流水）在 `Command` 里，
   「写完之后刷新界面」在 `Store` 的用例方法里。

域与文件对应：`settings` / `ledger` / `account` / `category` / `txn` / `debt` /
`budget` / `goal` / `recurring` / `template` / `backup`，写命令统一在 `commands.dart`。

## 三、状态层

| 文件 | 内容 |
| --- | --- |
| `store.dart` | `Store` 类体：字段（全部私有）、启动与加载、`after*` 重算、派生 getter |
| `store/state.dart` | 只读投影（extension）：`s.txns` / `s.accounts` / `s.cycleFrom` … |
| `store/actions.dart` | 用例方法（extension）：`addTxn` / `saveBudget` / `recalcBalances` … |
| `store/views.dart` | 两个分组视图：`s.stats.*`（统计口径与结果）、`s.filter.*`（筛选态） |

**为什么 state/actions/views 是 extension**：Dart 的类体不能跨文件（`part` 是顶层
文本插入，不能续写 class），而 `store.dart` 已经接近一千行。这三组东西各自只依赖
公开方法或只读投影，正好能用 extension 搬出去 —— 调用点一行都不用改。

**规矩**：`Store` 里不允许有公开可变字段。页面想改状态只能调方法
（`switchTab`、`setStatBasis`、`addTxn`、`saveBudget`…）。
新增只读投影 → 加在 `store/state.dart`；新增一组状态 → 参照 `views.dart` 加视图。

写路径的三步检查见 `docs/写入口清单.md` 第五节。

## 五、这些约束由谁守

`test/architecture_test.dart` 七条：

1. `lib/data` 不依赖 Flutter / design
2. `Repo` 门面只做转发
3. `BillCsv` 门面只做转发
4. `models.dart` 不含公开顶层声明（实体必须进 `models/*.dart`）
5. `models.dart` 的 `part` 与目录里的文件一致（不会留下列不编译的孤儿文件）
6. `Store` 没有公开可变字段
7. `store/state.dart` 的每个 getter 都有对应的私有字段

它们读源码做形状匹配，不测行为——所以改实现、改注释、改签名都不会误报。
