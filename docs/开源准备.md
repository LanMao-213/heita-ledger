# 公开仓库前检查清单

> 生成于 2026-10-22。本文记录「把仓库从私有改成公开」这件事**已经做到了哪一步**、**还差什么**。
> 参照的是 GitHub 官方的「公开前自查」思路:一旦公开,Git 历史里的每一行都会被搜索引擎和爬虫抓走,删掉也没用。

## 一、已经完成(可复现的自查)

| 项 | 结论 | 怎么验的 |
|---|---|---|
| 签名密钥是否入过库 | **没有** | `git log --all --oneline -- '*.jks' '*.keystore' 'key.properties'` 为空 |
| 密钥文件是否被忽略 | **是** | `git check-ignore -v android/key.properties android/app/release.jks` 命中 `android/.gitignore:12` 与 `:14` |
| 跟踪文件里有无凭证 | **无** | `git grep -lEi "BEGIN (RSA\|PRIVATE)\|ghp_\|AKIA[0-9A-Z]{16}\|sk-[a-zA-Z0-9]{20,}"` 无命中 |
| 有无身份证/手机号 | **无**(仅 `pubspec.lock` 的 sha256 误报) | `git grep -nE "1[3-9][0-9]{9}"` 只命中哈希串 |
| 本机绝对路径 | **已脱敏** | 文档与 `tools/` 脚本里的 `C:/Users/<用户名>/...` 已改为相对路径、环境变量或 `<占位符>` |
| 构建产物是否入过库 | **否** | `git ls-files \| grep -E "^build/\|^\.dart_tool/"` 为空 |
| 分支是否收敛 | **是**,只剩 `main` + `feat/v2-merge` | `gh api repos/{owner}/{repo}/branches` |

## 二、还要你决定/操作的三件事

### 1. 许可证(必须你定,这是一次法律授权)

| 选项 | 含义 |
|---|---|
| **MIT** | 别人可自由使用、修改、商用、闭源再发布,只需保留版权声明。个人开源最常见 |
| **Apache-2.0** | 同 MIT,外加专利授权与「修改过的文件要标注」 |
| **不加** | 默认「保留所有权利」:别人能看到,但法律上不能复制/修改/分发 |

> 如果目的只是"让朋友方便访问代码",公开 + MIT 最省事;
> 如果只是想展示、不希望别人拿去用,**不加**更合适。

### 2. 仓库元信息(在 GitHub 网页设置,或让我用 API 改)

- Description / Topics(建议:`flutter` `android` `accounting` `offline-first` `local-first` `sqlite`)
- 是否保留 `Releases` 里的历史 APK(1.1.x 那批是 **debug 签名**,和现在的正式签名不是同一个证书,**跨这条线不能覆盖安装**——公开后请在 Release 说明里写清)

### 3. 可见性切换本身

在 Settings → General → Danger Zone → Change repository visibility。
**这一步不可逆地改变了"谁都能看到"这件事**:即使之后改回私有,代码可能已被 fork 或缓存。

## 三、公开之后要守的两条

1. **`android/key.properties` 与 `*.jks` 永远不要提交**。它们还在你本地(签名要用),已被 `.gitignore` 挡住。别用 `git add -f` 绕过。
2. **每次发版前跑一遍自查**(复制即用):

```bash
# 凭证泄漏
git grep -lEi "BEGIN (RSA|PRIVATE)|ghp_|AKIA[0-9A-Z]{16}|sk-[a-zA-Z0-9]{20,}"
# 本机路径
git grep -nE "[A-Z]:/Users/|[A-Z]:\\\\Users\\\\"
# 密钥文件
git log --all --oneline -- '*.jks' '*.keystore' 'key.properties'
```
