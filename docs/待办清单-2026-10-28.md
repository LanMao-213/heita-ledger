## 阻塞点

### B1 · 提醒能力需要新增敏感权限，与「极简权限」形象冲突

「周期开始当天提醒」在当前工程里**没有任何现成能力**：

- `pubspec.yaml` 无通知类依赖
- `main/AndroidManifest.xml` 一个权限都没声明
- `lib/` 内无通知实现

若走系统通知，需要引入 `flutter_local_notifications`，并新增：

- `POST_NOTIFICATIONS`（Android 13+ 运行时申请）
- Android 12+ 若要准时，还需 `SCHEDULE_EXACT_ALARM` / `USE_EXACT_ALARM`（受应用市场审核关注的敏感权限）

项目的核心卖点是「零联网权限」，加通知**不破**这条红线（本地通知不联网），但会扩大权限面。两种解法：

1. **应用内提示**（零权限）：周期首日打开 App 时在计划页顶部给一条可关闭的提示条，点进去当次选账户。实现量小，不新增权限。
2. **系统通知**：能主动触达，但要新增两条权限，且在华为等机型上需额外适配后台自启。

倾向 1，需要拍板。

### B2 · 正式分发与现有安装签名冲突

手机上 `com.heita.ledger` 是 debug 签名（`D8:B6:FA:69:…`），仓库外的正式密钥 `release.jks`（`9F:46:70:B1:…`）签出来的包无法覆盖安装。要让真实用户正常升级，只有两条路：

- 继续保持 debug 签名分发（不像正式产品，且 debug key 泄露风险）
- 让现有用户卸载重装（账目清空，必须先导出备份）

这个矛盾在 v1.6.0 上线前必须定，否则「升级」这件事本身走不通。

### B3 · 手机解锁状态

真机操作（安装、点击、截图）需要设备解锁。本轮已出现过一次 AOD 息屏导致 `adb install` 看似失败（实际是华为应用市场的安装确认页在等待点击）。后续真机步骤若遇 `SIGTERM` 或空输出，先截图看 `mCurrentFocus`，不要当成失败重试。
