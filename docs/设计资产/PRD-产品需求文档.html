01产品定位

一款把「记一笔」的成本压到最低的本地记账工具。数据只存在你的手机里。

一句话定位

给讨厌复杂记账软件的人用的极简账本。没有账号、没有广告、没有服务器，打开就能记，记完就走。

目标用户

  • 想记账但被主流 App 的理财、社区、会员体系劝退的人
  • 对隐私敏感、不愿把收支数据交给第三方的人
  • 需要区分个人 / 家庭 / 生意多套账目的人
  • 习惯用 Excel 做二次分析，需要能自由导入导出的人

核心差异化

维度本产品主流记账 App 的常见做法
数据归属纯本地 SQLite，零联网云端账号，数据在厂商服务器
账号体系无注册无登录手机号注册，强制登录
界面黑白灰 + 单点红，全站线稿图标彩色分类图标，视觉信息密集
数据自由Excel 双向导入导出，字段完全公开导出受限或需付费解锁
功能边界只做记账，不做理财/社区/会员账单分期、投资、社区、广告
产品主线：记账 → 看明白花在哪 → 导出到 Excel 深挖。三件事之外的功能一律不进 V1。

02已确认的关键决策

以下是本次评审确定的方向，后续设计以此为准。

决策项结论影响
账本与账户 多账本 + 账户 数据模型需 4 张核心表（账本 / 账户 / 分类 / 交易），明细与图表都要带账本上下文
记账方式 手动 + 记账模板 + 周期账单 新增 2 张表（模板 / 周期账单），记一笔面板要留模板入口
数据存储 纯本地，零联网 不引入任何网络 SDK，换取无需 App 备案的资格
平台 Android 单端，API 26+ 不需要 iOS 打包与 Apple 开发者账号
视觉 黑白灰红，一笔线稿图标 支出用纯黑、收入用次级灰，靠色重与 +/− 区分，不用红绿
名称 黑塔消费日记 桌面显示名建议用短名，完整名留作用户可见的关于页
⚠️ 一条不可触碰的技术红线
本项目坚持「单机应用」实现，以此换取国内安卓商店的免 App 备案资格（华为官方口径：断网后所有核心功能可用即为单机应用，提交时勾选「单机APP」）。
因此禁止引入任何统计、崩溃上报、广告、埋点 SDK，禁止任何 HTTP 请求。哪怕是启动页的一次 ping，也会导致备案审核不通过。

04数据模型

7 张表。这是整个项目最关键的部分——表结构一旦进入开发，改动成本远高于界面。

表：ledger 账本

字段类型说明
idINTEGER PK自增主键
nameTEXT NOT NULL账本名，如「日常」「家庭」「小店」
iconTEXT线稿图标键
sort_orderINTEGER排序权重
is_defaultINTEGER0/1，App 启动时默认进入哪个账本

规则：系统始终保证至少存在一个未归档账本。删除账本时若其下有交易，只允许归档不允许删除。

表：account 账户（全局共享）

字段类型说明
idINTEGER PK
nameTEXT NOT NULL如「招行储蓄卡」「微信零钱」
typeTEXT NOT NULLcash / debit / credit / alipay / wechat / other
iconTEXT线稿图标键
initial_balanceINTEGER DEFAULT 0初始余额，单位为分
include_in_totalINTEGER DEFAULT 1是否计入总资产
sort_orderINTEGER
created_atINTEGER
archived_atINTEGER NULL

为什么账户不挂账本：银行卡、支付宝是「钱包」，一个人就那几张，跨账本共享更符合直觉。家庭账和生意账用的都是同一张卡。

表：category 分类（归属账本）

字段类型说明
idINTEGER PK
ledger_idINTEGER NOT NULL FK所属账本
parent_idINTEGER NULL FK子分类。V1 恒为 NULL，字段预留避免日后迁移
typeTEXT NOT NULLexpense / income
nameTEXT NOT NULL
iconTEXT NOT NULL线稿图标键（见视觉规范）
sort_orderINTEGER
is_systemINTEGER DEFAULT 0系统预置分类不可删除，只能归档
archived_atINTEGER NULL

为什么分类分账本：「进货成本」这种分类只对生意账本有意义，「奶粉」只对家庭账本有意义。新建账本时自动复制一份默认分类集，用户再按需增删。

表：txn 交易（核心）

字段类型说明
idINTEGER PK
ledger_idINTEGER NOT NULL FK所属账本（删除保护：有交易的账本只能归档）
typeTEXT NOT NULLexpense / income / transfer
amountINTEGER NOT NULL单位为分，恒为正数；正负由 type 决定
category_idINTEGER NULL FK转账时为 NULL
account_idINTEGER NULL FK转出账户；转账时为转出方
to_account_idINTEGER NULL FK仅 transfer 使用
dateTEXT NOT NULLYYYY-MM-DD
timeTEXT NULLHH:mm，可空
noteTEXT备注
template_idINTEGER NULL FK来源模板，用于统计模板使用率
recurring_idINTEGER NULL FK来源周期账单
import_batchTEXT NULL导入批次号，用于「撤销本次导入」
created_atINTEGER NOT NULL
updated_atINTEGER
deleted_atINTEGER NULL软删除，所有查询默认过滤

索引：(ledger_id, date DESC) · (account_id) · (category_id) · (import_batch)

为什么金额必须用整数存「分」
浮点数无法精确表示小数，0.1 + 0.2 = 0.30000000000000004。记账软件一旦累计几千笔， 结余就会出现「差 1 分」的诡异现象，而且越查越乱。所有金额在存储和运算层一律用整数分，只在渲染时除以 100 并格式化。
为什么 date 用 TEXT 而不是时间戳
本地记账的归属单位是「日期」而非「时刻」，不涉及时区换算。用 YYYY-MM-DD 字符串可以直接按字典序排序、 直接 LIKE '2026-10%' 按月筛选、直接 GROUP BY substr(date,1,7) 做月度统计——比时间戳简单得多， 也避免了「晚上 11 点记的账算哪天」这类时区坑。

表：recurring 周期账单

字段类型说明
idINTEGER PK
ledger_idINTEGER NOT NULL FK
nameTEXT NOT NULL如「房租」「视频会员」
type / category_id / account_id / to_account_id / amount / note—同 txn，amount 必填
freqTEXT NOT NULLdaily / weekly / monthly / yearly
intervalINTEGER DEFAULT 1每 N 个周期，如「每 2 周」

enabledINTEGER DEFAULT 1
next_run_dateTEXT NOT NULL下次应触发日
last_run_atINTEGER NULL
⚠️ 周期账单的实现真相——请务必理解这一条
本 App 不联网、无后台服务、无权限常驻，因此无法在后台按时执行任何任务。 所谓「自动记账」的真实机制是：每次打开 App 时，扫描所有 next_run_date ≤ 今天 的规则并补记， 补记产生的交易日期用规则应触发日，而不是打开 App 的日期。

举例：房租规则为每月 1 号，你 10 月 5 日才打开 App —— 会补记一笔日期为 2026-10-01 的交易，而不是 10-05。

界面上必须明确告知这一点（在周期账单页底部放一行灰字说明），否则用户会误以为漏记而重复手动记账。

表：setting 键值配置

key用途
default_ledger_id默认账本
active_ledger_id上次退出时所在账本
pin_hash密码锁哈希（加盐），无密码时为空
dark_mode深色模式开关
auto_backup本机自动备份开关

附录 · SQLite 建表语句（DDL） 
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;

CREATE TABLE ledger (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT    NOT NULL,
  icon          TEXT,
  sort_order    INTEGER NOT NULL DEFAULT 0,
  is_default    INTEGER NOT NULL DEFAULT 0,
  created_at    INTEGER NOT NULL,
  archived_at   INTEGER
);

CREATE TABLE account (
  id              INTEGER PRIMARY KEY AUTOINCREMENT,
  name            TEXT    NOT NULL,
  type            TEXT    NOT NULL,
  icon            TEXT,
  initial_balance INTEGER NOT NULL DEFAULT 0,
  include_in_total INTEGER NOT NULL DEFAULT 1,
  sort_order      INTEGER NOT NULL DEFAULT 0,
  created_at      INTEGER NOT NULL,
  archived_at     INTEGER
);

CREATE TABLE category (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  ledger_id   INTEGER NOT NULL REFERENCES ledger(id),
  parent_id   INTEGER REFERENCES category(id),
  type        TEXT    NOT NULL,
  name        TEXT    NOT NULL,
  icon        TEXT    NOT NULL,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  is_system   INTEGER NOT NULL DEFAULT 0,
  archived_at INTEGER
);
CREATE INDEX idx_category_ledger ON category(ledger_id, type, sort_order);

CREATE TABLE txn (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  ledger_id     INTEGER NOT NULL REFERENCES ledger(id),
  type          TEXT    NOT NULL,
  amount        INTEGER NOT NULL,
  category_id   INTEGER REFERENCES category(id),
  account_id    INTEGER REFERENCES account(id),
  to_account_id INTEGER REFERENCES account(id),
  date          TEXT    NOT NULL,
  time          TEXT,
  note          TEXT,
  template_id   INTEGER REFERENCES template(id),
  recurring_id  INTEGER REFERENCES recurring(id),
  import_batch  TEXT,
  created_at    INTEGER NOT NULL,
  updated_at    INTEGER,
  deleted_at    INTEGER
);
CREATE INDEX idx_txn_ledger_date ON txn(ledger_id, date DESC);
CREATE INDEX idx_txn_account     ON txn(account_id);
CREATE INDEX idx_txn_category    ON txn(category_id);
CREATE INDEX idx_txn_batch       ON txn(import_batch);

CREATE TABLE template (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  ledger_id     INTEGER NOT NULL REFERENCES ledger(id),
  name          TEXT    NOT NULL,
  type          TEXT    NOT NULL,
  category_id   INTEGER REFERENCES category(id),
  account_id    INTEGER REFERENCES account(id),
  to_account_id INTEGER REFERENCES account(id),
  amount        INTEGER,
  note          TEXT,
  icon          TEXT,
  sort_order    INTEGER NOT NULL DEFAULT 0,
  use_count     INTEGER NOT NULL DEFAULT 0,
  last_used_at  INTEGER,
  created_at    INTEGER NOT NULL
);

CREATE TABLE recurring (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  ledger_id     INTEGER NOT NULL REFERENCES ledger(id),
  name          TEXT    NOT NULL,
  type          TEXT    NOT NULL,
  category_id   INTEGER REFERENCES category(id),
  account_id    INTEGER REFERENCES account(id),
  to_account_id INTEGER REFERENCES account(id),
  amount        INTEGER NOT NULL,
  note          TEXT,
  freq          TEXT    NOT NULL,
  interval      INTEGER NOT NULL DEFAULT 1,
  by_month_day  INTEGER,
  by_week_day   INTEGER,
  start_date    TEXT    NOT NULL,
  end_date      TEXT,
  auto_post     INTEGER NOT NULL DEFAULT 1,
  enabled       INTEGER NOT NULL DEFAULT 1,
  next_run_date TEXT    NOT NULL,
  last_run_at   INTEGER
);
CREATE INDEX idx_recurring_due ON recurring(enabled, next_run_date);

CREATE TABLE setting (
  key   TEXT PRIMARY KEY,
  value TEXT
);

注：DDL 中 txn 引用了在其之后定义的 template / recurring，SQLite 允许此写法（外键在运行时校验）。若需严格顺序，可先建这两张表再建 txn。

05功能需求

优先级：P0 V1.0 必须有　P1 V1.1　P2 远期

M1 · 账本管理 P0

  • 新建 / 重命名 / 换图标 / 拖动排序 / 归档
  • 指定默认账本；删除当前账本时自动切回默认账本
  • 新建账本时可勾选「复制现有账本的分类」，否则使用内置默认分类集
  • 有交易的账本只能归档不能删除；归档后数据保留、列表隐藏
  • 明细页顶部显示当前账本名，点击弹出账本切换器（显示各账本月度结余）

M2 · 账户管理 P0

  • 六种类型：现金 / 储蓄卡 / 信用卡 / 支付宝 / 微信 / 其他
  • 设置初始余额；账户名、图标、排序
  • 「计入总资产」开关（信用卡等负债账户可关闭）
  • 显示各账户当前余额 = 初始余额 + Σ收入 − Σ支出 + Σ转入 − Σ转出
  • 有交易的账户只能归档不能删除
  • P1 总资产卡片与账户余额趋势

M3 · 分类管理 P0

  • 支出 / 收入两组，分别管理
  • 新增、改名、换图标（从线稿图标库选）、拖动排序
  • 系统预置分类不可删除，只能归档——避免历史账单丢失归属
  • 已被使用的分类不可删除，提示「该分类下有 N 笔记录，请先归档或改归其他分类」
  • P1 子分类（数据层已预留 parent_id）

M4 · 记一笔 P0

  • 三种类型分段切换：支出 / 收入 / 转账
  • 分类九宫格，选中态为黑色描边 + 白底
  • 数字键盘：最多 9 位整数 + 2 位小数；含「⌫」「清空」「完成」
  • 转账模式：分类区替换为「转出账户 → 转入账户」两个选择器，且两侧账户不可相同
  • 备注（24 字上限）、日期（默认今天）、时间（默认当前，可关闭）
  • 账户选择器，默认使用上次该分类所用的账户
  • 保存后返回明细页，新记录有短暂高亮
  • 「存为模板」按钮：把当前填写内容存成模板
  • 面板顶部展示最近使用的 3 个模板，点击一键填充

M5 · 记账模板 P0

  • 模板列表：增删改、排序、换图标
  • 字段预填策略：分类与账户必填；金额可填（一键录入）或留空（只省掉选分类的步骤）
  • 按 use_count 降序排列「常用模板」
  • 记一笔保存时若内容与某模板高度相似，提示「要存为模板吗？」

M6 · 周期账单 P0

  • 频率：每天 / 每周 / 每月 / 每年，支持「每 N 个周期」
  • 每月模式可选 1–31 号；选择 29–31 号时，小月自动落到当月最后一天
  • 「自动补记」开关：开 = 到期静默生成；关 = 生成待确认项，用户确认后才入账
  • 启用 / 暂停单条规则；设置起始日与结束日
  • 补记机制见 04 章的警示框——打开 App 时扫描补记，交易日期用规则应触发日
  • 页面底部必须有一行说明文字，告知用户补记逻辑
  • 补记历史可查，支持整批撤销

M7 · 明细 P0

  • 按日期倒序分组，日期行显示当天「支出 X · 收入 Y」小计
  • 顶部纯黑概览卡：本月结余、支出、收入、预算进度条
  • 月份左右切换；点击月份可跳到「选择年月」
  • 单条左滑删除（带撤销 toast），点击进入编辑
  • 空状态：本月无记录时显示引导文案与「＋」提示
  • P1 关键词搜索备注与金额
  • P1 筛选：分类 / 账户 / 金额区间 / 时间段

M8 · 图表 P0

  • 分类占比甜甜圈：按金额降序映射 10 级灰阶，金额越大颜色越深
  • 分类排行：图标 + 名称 + 笔数 + 金额 + 百分比 + 横向条形

  • P1 年视图、日历视图

M11 · 密码锁 P1

  • 4 位数字 PIN；支持系统生物识别（指纹/面容）
  • 冷启动与从后台返回超过 60 秒时验证
  • 忘记密码只能清空数据——本地无云端，这是架构决定的必然结果，设置密码时必须明确告知
  • P1 数据库加密（SQLCipher）—— 若做，需在 V1.0 建库时就启用，否则后期迁移成本高

M12 · 预算 P1

  • 总额预算 / 按分类预算
  • 明细页概览卡显示进度条：使用率 < 80% 白、80–100% 灰、超支 深灰
  • 超支时在图表页顶部给出提示（不用红色，保持黑白灰基调）

这是本产品的核心差异功能，也是用户数据「逃生舱」。字段定义一旦确定，向后兼容就是硬约束。

导出

保存位置

列结构（固定顺序，不含任何内部字段）

#列名格式说明

B时间HH:mm可空
C类型支出 / 收入 / 转账必填

刻意不导出 id、ledger_id 等内部字段：保持表格人可读、可直接在 WPS/Excel 里编辑后再导回。代价是导入时无法靠 id 做精确去重，改用业务字段比对（见下）。

导入

入口
我的 → 数据 → 从 Excel 导入
目标账本
默认导入到当前账本；若表格含「账本」列则按列值路由（账本不存在时先弹窗询问是否创建）
行为
追加，绝不覆盖已有数据

表头识别

模糊匹配，容忍首尾空格、全半角、大小写与常见别名。别名表：

标准列名可接受别名
日期时间/交易日期/记账日期/date
类型收支/收支类型/类别（与「分类」二选一时优先）/type
分类分类名称/类别（同上）/category
金额金额(元)/交易金额/amount
账户账户名称/付款账户/account
转入账户收款账户/目标账户
备注说明/note/remark

无法识别的列直接忽略，不报错。缺少「日期」或「金额」列时中止导入并提示。

字段解析规则

字段接受的输入异常处理
日期YYYY-MM-DD · YYYY/M/D · YYYY年M月D日 · Excel 日期序列号无法解析 → 该行标记错误
类型支出/收入/转账 · expense/income/transfer · 1/0（1=支出）空值默认按金额正负推断；无法判断 → 默认支出
金额去千分位逗号、去 ¥/￥/空格；支持负数负数自动判为支出并覆盖类型；0 → 标记无效
分类文本；转账行忽略不存在时按设置处理：默认自动创建，可改为「归入其他」
账户文本；不存在时自动创建，类型默认「其他」空值 → 账户留空
备注文本，超 24 字截断并提示

导入预览页

解析完成后不直接写库，先展示三类结果让用户确认：

  • 可导入 N 条 —— 正常记录
  • 疑似重复 M 条 —— 判定条件：日期 + 金额 + 类型 + 分类 + 备注 五项全部相同。逐条勾选是否跳过，默认全选跳过
  • 格式错误 K 条 —— 列出 Excel 行号与失败原因，供用户回去修表

确认后写入，并生成一个 import_batch 批次号；结果页提供「撤销本次导入」按钮，可整批回滚。

为什么重复判定不用 id：导出的表格不含内部 id，用户可能在 Excel 里手改过再导回。用业务字段组合判定虽不完美， 但配合「默认跳过 + 可逐条取消」的交互，误判代价可控；反过来若强行去重导致漏导入，用户的账就丢了一笔，后果更严重。

07非功能需求

性能

场景指标
冷启动到明细页可交互< 800ms
明细列表滚动10,000 条数据下稳定 60fps（需分页加载 + 懒构建）
首页统计计算< 100ms
导出 10,000 条到 Excel< 5s，期间显示进度
解析 10,000 行导入文件< 3s

数据与安全

  • 数据库文件：应用私有目录 databases/ledger.db，文件名中性不绑定品牌，便于日后改名
  • 本机自动备份：每次冷启动与退出时复制一份数据库，保留最近 7 份，超出滚动删除
  • 删除操作一律软删除（deleted_at），配 5 秒撤销窗口
  • P1 若启用 SQLCipher，需在 V1.0 建库时即开启

隐私与网络

零网络请求。不得引入统计、崩溃上报、广告、推送、埋点等任何 SDK。这是换取「单机应用」免备案资格的前提，也是产品的核心承诺。

兼容与适配

  • Android 8.0（API 26）及以上
  • 适配深色模式；全面屏手势区避让；系统字体缩放到 1.3 倍不破版
  • 横屏不做适配（记账类 App 无需横屏）
  • 语言：简体中文；金额与日期遵循中文习惯

无障碍

  • 所有线稿图标配 TalkBack 可读的文字标签
  • 仅靠颜色区分的信息（支出黑 / 收入灰）必须同时有 − / + 符号冗余
  • 点击区域不小于 48dp

09明确不做的事

写清楚「不做什么」和写清楚「做什么」同样重要——它能防止项目在中途膨胀失控。

不做原因
❌ 联网、账号、云同步破坏「单机应用」定位，会失去免备案资格，也会引入服务器成本与隐私风险
❌ 理财、投资、基金净值记账工具不是资产管理工具，混在一起会让核心流程变复杂
❌ 社区、分享、排行榜需要联网与账号，且与产品气质冲突
❌ 广告与付费墙数据是本地的，广告既无必要也伤害体验
❌ 信用卡账单分期、贷款计算复杂金融功能，目标用户不需要
❌ 语音记账（V1）需要联网 ASR 或本地大模型，前者违反红线，后者体积过大
❌ 自动同步微信/支付宝账单需要读取通知或无障碍权限，隐私风险高且易被商店下架
