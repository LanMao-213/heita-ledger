## 1. 项目现状

**导航收敛（1.7.3 的唯一主题）**

- 侧拉栏：五组十九项 → **1 个动作行（转账）+ 3 组共 12 项**。账本组：账户管理 / 分类管理 / 账本管理 / 记账模板 / 周期账单 / 账单日；数据组：导出 Excel / 导入账单 / 备份与恢复 / 数据安全；帮助组：帮助与引导（帮助说明、重看使用引导进二级菜单）。
- 原则：**抽屉是唯一的设置入口，底栏是唯一的页面切换入口**。删掉了和底栏重复的「导航」组、和底栏「+」重复的「常用」组。
- 「我的」页只剩五块：净资产卡 / 导出当前筛选结果 / 偏好 / 清空全部数据 / 关于。唯一留在本页的导出是「导出当前筛选结果」——它依赖明细页当下的筛选状态，是上下文动作，搬进全局面就失效了。
- 顺带修掉 9 个文件里的过期指引（帮助页、空态提示、二次确认都在教用户「去我的 → 账户管理」）。这类文案**任何测试都抓不到**，是 `grep "我的 → "` 手工扫出来的。

**并入 1.7.2 的数据修复**（不报错但算错的那一类）

- Excel 往返不再把转账降级成支出，也不再丢负数流水；
- 周期账单在月末不再漂移；
- v4→v5 的预算迁移按账单日归期，不再一律归月初；
- schema v10→v11 补了 `idx_txn_to_account`。

**架构现状**

- 金额全程 `int` 存「分」，没有 `double`；日期 `TEXT 'YYYY-MM-DD'`，月份 `'YYYY-MM'`。
- 写入只有一个入口 `lib/data/command.dart`：`WriteGateway` 不向业务暴露 `Database`，事务边界只有一处。
- 加密备份 = AES-256-GCM + PBKDF2(210000)，已用 `Isolate.run` 移出主 isolate。
- 真机验证：Redmi 23054RA19C / Android 15；`.dev` 后缀包与正式包并存安装，互不覆盖。

## 2. 核心模块

分层方向：`data` 在最底，`store` 依赖 `data`，`pages` / `widgets` 只读 `store` 的投影。

| 路径 | 职责 | 改动注意 |
| --- | --- | --- |
| `lib/data/` | 纯 Dart 数据层：模型、建表迁移、查询、导入导出、备份 | 不 import Flutter、不 import design。违反了 `architecture_test.dart` 直接报文件名 |
| `lib/data/models.dart` + `models/*.dart` | `models.dart` 只是库入口（import / part / 一个私有 helper），实体在各分部 | 新实体加进 `models/`，不要写进入口文件；`part` 列表要与目录一致 |
| `lib/data/db.dart` | 建表、索引、种子、迁移链 `onUpgrade` | 任何表结构变动都要升 `_version` 并写迁移；迁移必须幂等 |
| `lib/data/command.dart` | `Command` / `WriteGateway`：一次写入一个事务 | 新的写路径都从这进；别在页面或 Repo 里另起事务 |
| `lib/data/repo.dart` + `repo/*.dart` | `Repo` 门面 + 11 个域实现（settings / ledger / account / category / txn / debt / budget / goal / recurring / template / backup），写命令在 `commands.dart` | 门面只允许一行转发；`Repo` 里不放跨多次写入的业务编排 |
| `lib/data/backup_service.dart` + `backup/*.dart` | 备份门面 + 容器层：payload 校验 / 明文 / 加密容器 / 整库恢复 / 自动快照 | 字段级兼容在 `backup_compat.dart`，老文件读进来要能补齐字段 |
| `lib/data/bill_csv.dart` + `bill/*.dart` | 支付宝 / 微信账单 CSV：解码嗅探 → 找表头 → 列对齐 → 去重 | 对外只有 4 个入口：`parse` / `parseAmount` / `parseDate` / `markDuplicates` |
| `lib/data/excel_service.dart` | Excel 导入导出的列序与表头约定（同一份列序也是导入的识别依据） | 改列序 = 改兼容性，导入侧的识别会一起崩 |
| `lib/data/integrity.dart` `cycle.dart` `pacing.dart` `calc.dart` | 对账修复 / 归属期纯函数 / 预算节奏 / 金额四则求值 | 都是纯函数，优先补单测而不是接进 UI 再调 |
| `lib/store.dart` + `store/{state,actions,views}.dart` | 唯一持有可变状态的地方；`after*` 重算与派生 getter | `Store` 不允许公开可变字段；三组 extension 是「类体不能跨文件」的绕法，调用点不用改 |
| `lib/pages/` `lib/widgets/` | 界面层。`app_drawer.dart` 是 1 个动作行 + 3 组 12 项；`settings_actions.dart` 放设置类动作的公开函数，「我的」与抽屉共用 | 界面层不写业务判断：金额用 `Fmt`、归属期用 `Store` 返回值、保存分支用 `RecordDraft` |
| `lib/design/` | `tokens.dart`（颜色 / 字号 / 间距 / 圆角唯一来源）、`palette.dart` 六套皮肤、`theme_ctrl.dart` 当前皮肤 | 颜色只取 `C`；每套皮肤只换色，不引入装饰色 |
| `test/` | 699 条。`architecture_test.dart` 七条守结构（读源码形状匹配，不测行为） | 改实现、改注释、改签名不会误报；但字符串/注释里的同名文本会命中 |

## 3. 使用与部署

```bash
flutter pub get
flutter analyze --fatal-infos      # 必须 0 issue
flutter test                       # 必须全绿
flutter run --release              # 真机
```

- **版本号要改两处**：`pubspec.yaml` 的 `version:` 与 `lib/app.dart` 的 `kAppVersion`。「我的」页底部显示的是后者，两个不同步会出现「界面说 1.7.2、安装包是 1.7.3」。
- 构建号规则：只修 bug 升最后一位，加功能升中间位，`+` 后每次发版 +1（只给 Android 用）。
- 安装与并存：包名带 `.dev` 后缀的调试包可与正式包并存，互不覆盖；真机已验证（Redmi 23054RA19C / Android 15）。
- 签名：`release.jks` 从不进版本库；`verify_apk` 要求非 debug 签名。手机上现有安装是 debug 签名，正式密钥包**无法覆盖**，只能卸载重装（账目清空）——见 OD-04。
- **发布受阻（当前环境）**：本机 `github.com:443` 不可达（代理只放通 `api.github.com`），`git push` 会失败。合并 `main`、打 `v1.7.3` 标签这两步要先换网络或补代理规则再执行。代码改动目前只在本地分支，别当成已备份。
- 公开前的检查：`docs/开源准备.md` 有命令清单；提交信息也是公开内容，`python tools/privacy_scan.py --history --messages` 会拦本机路径与真实邮箱。
- 界面有改动要把 `build/visual/` 的截图贴进 PR；新页面必须过截图自检，不允许布局溢出。

## 5. 维护要点（六个会咬人的地方）

1. **金额精度** — `lib/data/models/fmt.dart` 与所有模型字段：金额一律 `int` 存「分」。一旦哪里冒出 `double`，就会出现 0.01 级误差，且只在跨期汇总时显形；表达式求值走 `data/calc.dart`（209 行，四则、不含括号），不要在页面里自己 split 再 parse。
2. **迁移幂等** — `lib/data/db.dart`：改表必须升 `Db._version` 并写 `onUpgrade`，且迁移要能重跑。种子数据或索引建两遍，老用户库会当场坏掉，而且没有回滚路径（本地无云备份，这是单机 App 最贵的错）。v11 补的是 `idx_txn_to_account`。
3. **主题整树重建** — `lib/design/theme_ctrl.dart`：换肤走整树重建，页面里提前缓存下来的颜色或尺寸不会跟着刷新。表现为「切了皮肤，某块还是旧色」；截图自检能露馅，单测不会。
4. **架构守卫正则口径** — `test/architecture_test.dart`：七条都是读源码做形状匹配。自己加规则或改实现时，注释、字符串里的同名文本也会被命中，出现「明明没违反却红了」。先读这条测试的匹配写法再改代码，别急着删断言。
5. **测试夹具缺表** — 涉及数据库的 widget 测试：开库与造数据必须包在 `tester.runAsync` 里，假时钟里 await 真实 I/O 会永久卡死（不是超时，是挂住）。另外手写建库的夹具若漏建 v11 新增的索引，查询会静默走全表——测试照样绿，只是慢。
6. **换行符 CRLF** — 仓库文档（`README.md` / `CHANGELOG.md` / `docs/*.md`）是 CRLF。用工具批量改写时若落成 LF，整篇 diff 会变成「全文修改」，PR 无法 review，历史追溯也会断掉。写文件时显式保留 CRLF。
