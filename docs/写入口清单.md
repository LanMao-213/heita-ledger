# 写入口清单（数据层）

> 维护约定：**新增任何会改数据的代码，先在这张表里找自己属于哪一类。**
> 判断标准只有一条 —— 这次写入是不是「一条 SQL 就能说完」。

---

## 一、必须走 `WriteGateway.run`（一次写多行 / 多表）

这些是唯一会留下「写了一半」的路径。事务边界统一由 `WriteGateway.run` 提供，
业务代码不接触 `Database`，所以**忘记开事务在结构上不成立**。

| 方法 | 一次事务里做了什么 | 校验 |
| --- | --- | --- |
| `Repo.insertTxn` | 插流水 + 改账户余额 | 动过的账户 |
| `Repo.updateTxn` | 回滚旧余额 → 改流水 → 应用新余额 | 旧账户 + 新账户 |
| `Repo.deleteTxn` | 回滚余额 + 删流水 | 动过的账户 |
| `Repo.createDebt` | 建 `debt` + 插本金流水 + 改余额 | 本金账户 |
| `Repo.repayDebt` | 插还款流水 + 改余额 + 必要时标记结清 | 还款账户 |
| `Repo.deleteDebt` | 逐条回滚关联流水的余额 → 删流水 → 删 `debt` | —（删完即无） |

对应的命令类都在 `lib/data/repo.dart` 末尾（`_InsertTxn` / `_UpdateTxn` / `_DeleteTxn` /
`_CreateDebt` / `_RepayDebt` / `_DeleteDebt`），`apply` 里只有业务语义。

## 二、单条 SQL，本身原子，**不需要**网关

| 方法 | 说明 |
| --- | --- |
| `setSetting` / `insertLedger` / `updateLedger` / `deleteLedger` | 单行；`ledger` 的子表靠 `ON DELETE CASCADE` |
| `insertAccount` / `updateAccount` / `deleteAccount` | 单行 |
| `Repo.saveAccount` | 单条 `UPDATE`（同时写 `balance_cents` 与 `opening_cents`） |
| `insertCategory` / `updateCategory` / `setCategoryArchived` | 单行 |
| `setBudget` | 「删」与「插」是互斥分支，每次只执行一条 |
| `addFunds` / `setDebtClosed` | 单条 `rawUpdate` / `update` |
| `insertGoal` / `updateGoal` / `deleteGoal` | 单行 |
| `insertRecurring` / `updateRecurring` / `deleteRecurring` | 单行 |
| `insertTemplate` / `updateTemplate` / `deleteTemplate` / `touchTemplate` | 单行 |

> 硬给这些套事务只是浪费 —— SQLite 的单条语句本身就在隐式事务里。

## 三、自带事务、但还没搬进网关（技术债，按需处理）

| 位置 | 现状 | 为什么先不搬 |
| --- | --- | --- |
| `Db.wipeAllData` | 删 9 表 + 重建种子，同一事务 | 在 `Db` 内部，搬进来会形成 `Db → WriteGateway → Db` 的循环依赖 |
| `Repo.replaceTables` | 清 10 表 + 灌备份，同一事务 | 同上；且它天然是「整库替换」，语义特殊 |
| `Repo.runDueRecurring` | 每条规则插流水在一个事务里；「推进 `next_run_date`」在事务外，靠 `(recurring_id, date)` 幂等护栏兜住 | 要搬得先把「遍历规则 + 逐期补」的循环结构拆开，属于另一件事 |
| `Repo.backfillMissingPeriods` | 一批 `batch.update`，外部包了事务 | 纯数据修补，不涉及余额 |

这四处**行为都是对的**（有事务、或有幂等兜底），只是没走统一入口。
判断标准：只要将来改动它们时出现了「第二条 SQL」，就必须搬。

## 四、网关的校验只在 debug / 测试里跑

`kVerifyWrites = !bool.fromEnvironment('dart.vm.product')`：

- **release 包**：常量折叠成 `false`，`Verifier` 里整段代码被编译器消掉，零开销；
- **debug / `flutter test`**：每次写入**提交之后**校验动过的账户，`balance == opening + 流水合计`。

校验跑在提交之后而不是事务里：它只警告、不回滚，占着事务只会延长持锁时间，
还会让界面测试的「点保存 → 等一会儿 → 断言」变脆（`test/support/wait_write.dart`
就是为此加的）。

校验失败**只警告不阻断**（`WriteGateway.warnings`）。这是有意的：用户手机上真实存在
的库可能带着 1.4.4 之前的漂移，抛异常会让那次记账直接失败 —— 拿历史问题卡住用户
当下要办的事，比问题本身更糟。机械证据放在测试里（`test/command_test.dart` 断言
正常记账时 `warnings` 为空），CI 会红。
