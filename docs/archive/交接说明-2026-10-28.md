### 2. 版本号规则有一处**明确例外**

本文开头的约定（也在 `CHANGELOG.md` 顶部）是「加功能升中间位，只修 bug 升最后一位」。
但 1.5.1 这批**含功能变更**（默认皮肤改了、分类预算过滤、趋势卡提示移除），
按约定本应是 1.6.0。

这是用户明确要求「锁在 1.5.x、只升补丁位」的结果，**只此一次**。
下一次做功能变更时不要沿用这个先例，否则版本号会失去「看号知改动」的意义。

### 3. 分支名与版本号不一致，不是笔误

分支是先按 1.6.0 开的，版本号后按要求改成 1.5.1。合并时可以顺手把分支名改掉，
但**不要**在合并时把 `pubspec.yaml` 又改回 1.6.0。

同理，本分支上那条功能提交的信息写的是 `feat(1.6.0): ...`，也与实际版本号不符 ——
它是按当时的计划写的，之后才改成 1.5.1。**以 `pubspec.yaml` 的 `1.5.1+25` 为准**，
不要根据提交信息判断版本。这条**没有**去改写历史：本仓库的历史已被改写过三次
（每次都让所有旧克隆失效），为了一行提交信息再加一次不值得。

## 4. 关键逻辑（读这几处就懂大半）

### 4.1 金额：全程 `int` 存「分」

没有 `double`，不靠四舍五入维持平衡，求和永远精确。

但**「显示」和「求值」是两套口径**，这是 1.5.0 出过 bug 的地方：

- `Calc.cents(expr)`：能不能存（非法表达式返回 null）
- `Calc.display(expr)`：此刻该显示什么（`1.` / `12+` 也要有值）
- `amountDraftText(input)`：记账面板的大字显示。**纯字面量按用户敲的原样**，
  含运算符才按计算结果去零。`4.3` 就该是 `4.3`。

### 4.2 主题：`C.xxx` 是运行时 getter

`design/tokens.dart` 里的颜色全是读 `ThemeCtrl.i.palette` 的 getter，
换肤时靠 `app.dart` 的 `ValueKey(ThemeCtrl.i.id)` 触发整棵子树重建。
代价是换肤会丢页面局部状态（滚动位置、展开的输入框），这是**刻意**的 ——
换肤是低频操作，让 446 处调用点各自监听主题不现实。

默认值只有一处定义：`palette.dart` 的 `kDefaultTheme`。`themeIdFromString()` 的回落、
`paletteOf()` 的兜底都指向它，改默认只需改这一行（外加同步注释与三处测试断言）。

### 4.3 记一笔面板：高度和底边不能各走各的

`record_sheet.dart` 的 `build` 只做「让位计算 + 外壳」，数值背后各有一段真机踩坑记录：

- 面板底边**始终贴着**「键盘或手势条」的上沿（`reserved = bottomInset`）
- 面板高度**只由内容决定**（不给 `minHeight` 钉满高）
- 数字键盘让位的方式是**被输入法 1:1 顶出去**（`_keypadSlotHeight`），不是自己收起

历史教训（都写在代码注释里）：1.4.x 用 `AnimatedSize` 的 150ms 和输入法 200~300ms 永远对不齐，
快了面板先塌、慢了可滚动区被压成 0，两种都表现为「面板跳了一下」。

**已知未解决**：`_keypadSlotHeight()` 在不足 40dp 时把槽位硬切到 0，面板总高会突减 40dp。
想让高度连续就得留碎边，但 `record_note_layout_test:105` 要求「备注框贴键盘上沿」，
两者不可兼得。下一版要重新设计。

### 4.4 分层是测试守着的

`test/architecture_test.dart` 用正则读源码，断言：

- `lib/data` 不许依赖 Flutter
- `Repo` 门面只许转发
- `Store` 没有公开可变字段

改结构时如果这几条红了，说明分层被破坏了，不要去改测试。

### 4.5 数据库迁移

改表结构必须升 `Db._version` 并写 `onUpgrade`，老用户数据不能丢。
v9 加的是两条部分唯一索引（周期账单重复生成、同一账本同一期两份总预算），
迁移时**先清存量重复再建索引**，周期流水一条不删。

## 5. 使用与运行

```bash
# 1. 装依赖（不要直接 flutter pub get，见下）
./tools/pub_get.sh

# 2. 跑起来
flutter run

# 3. 提交前必须过
flutter analyze --fatal-infos
flutter test
```

**为什么不能直接 `flutter pub get`**：仓库的 `pubspec.lock` 是按镜像 `pub.flutter-io.cn` 解析的，
直接跑会按当前源重写每个包的 `url` 字段 —— 版本一个不变，却多出 87 行脏改动。
`tools/pub_get.sh` 只是替你设了 `PUB_HOSTED_URL` 再调 pub。

**代理环境下跑测试必须剥掉代理变量**，否则 flutter_tester 的本地 WebSocket 被拦：

```bash
env -u HTTP_PROXY -u HTTPS_PROXY -u http_proxy -u https_proxy \
    NO_PROXY=localhost,127.0.0.1 flutter test
```

**出验证包（与已装应用并存，不动账目）**：

```bash
flutter build apk --release --target-platform android-arm64 -PappIdSuffix=.dev
# → com.heita.ledger.dev，与 com.heita.ledger 并存
```

**出包后必须验两遍**，两条都过才算能发：

```bash
export ANDROID_HOME="<你的 SDK 路径>"          # verify_apk.py 需要它找 aapt
python tools/verify_apk.py <apk路径>            # 七项：包名/版本/kAppVersion/签名/权限/图标/ABI
python tools/privacy_scan.py --artifacts <apk路径>
```

`verify_apk.py` 会核对 `pubspec.yaml`、`lib/app.dart` 的 `kAppVersion` 与包内真实版本三者一致 ——
改版本时漏改一处，这里会拦住。

## 6. 后续注意事项（踩过的坑，别再踩）

### 1. 真机命令看起来「失败」时先看屏幕

华为机型 `adb install` 会转交应用市场，弹出「安装成功 / 确认安装」页在等点击。
表现是命令 `SIGTERM` 或空输出，看起来像失败，实际在等确认。
先 `adb shell dumpsys window | grep mCurrentFocus`，若是 `InstallDistActivity` 或 AOD，说明在等操作。

### 2. 用截图量坐标必须先看真实分辨率

截图是全分辨率（1220×2700），而预览/模型看到的是缩放版（515×1124）。
按缩放比例手算点击坐标会全错。要么用 `uiautomator dump` 的 `bounds`，
要么用 PIL 按颜色扫包围盒。

### 3. 正式分发的签名矛盾（未解决，需拍板）

手机上现有安装是 debug 签名，`release.jks` 签的包覆盖不了。两条路：继续用 debug 签名分发
（不像正式产品，且 debug key 泄露风险），或让老用户卸载重装（账目清空，必须先导出备份）。
**在这个矛盾解决前，「升级」这件事走不通。**

### 4. 构建路径不能含用户名

`libapp.so` 会嵌入构建期绝对路径（Dart AOT 行为，无配置可关）。
正式发版要先 `git archive` 导出到中性路径再构建，否则等于把本机路径随 APK 发出去。

### 5. Git Bash 下的 `adb shell` 路径

`/sdcard/...` 会被 MSYS 转成 Windows 路径。跑 `uiautomator dump` 之类要么
`export MSYS_NO_PATHCONV=1`，要么把参数写成 `//sdcard/...`。

### 6. `keytool` 要喂 Windows 路径

在 `MSYS_NO_PATHCONV=1` 下，`keytool` 收到 MSYS 风格路径（`/c/Users/...`）会报「密钥库文件不存在」。
要喂 Windows 风格（盘符开头）的绝对路径。

### 7. 推送前一律先跑隐私扫描

```bash
python tools/privacy_scan.py                       # 工作树
python tools/privacy_scan.py --history             # 历史树
python tools/privacy_scan.py --history --messages  # 提交信息（最容易被忘）
```

**提交信息也算公开内容**。这个仓库的历史被改写过三次，其中第三次就是因为
提交信息里自己写着主机名。
