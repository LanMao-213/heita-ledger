## F1 名目候选（双轮盘选择）

**目标**：选了分类，直接从轮盘里挑名目，选完分类和备注一起生效。对方这块「左分类右名目」的联动，是它手感最好的地方。

**形态（已定：方案① 点开弹面板）**：记一笔里的分类区缩成一行摘要「餐饮 · 午饭」，点它从底部弹出双轮盘 —— 左轮分类、右轮该分类的名目，右轮跟随左轮实时联动；右轮末尾留一项「自定义…」，点了跳回备注输入框。确认后分类与备注一并写入。

**改动点**

| 文件 | 改法 |
|---|---|
| `lib/data/note_hints.dart`（已完成） | 词表：支出 10 类 62 词、收入 6 类 16 词；按「类型 + 分类名」两张表查，避免支出/收入各有一个「其他」互相覆盖 |
| `lib/widgets/picker_wheels.dart`（新） | 双轮盘组件：两列 `CupertinoPicker`，左列变化时重建右列 |
| `lib/widgets/record_sheet.dart:571` 附近 | 分类九宫格换成一行摘要（图标 + 分类名 + 名目 + 展开箭头），点击打开双轮盘面板 |
| 同文件 `_RecordSheetState` | 保存时写入 `categoryId` 与 `note`；编辑态需要把已有备注反查到名目（若命中高亮，否则显示「自定义」） |

**兜底规则**：用户自建分类没有词表项 → 右轮只显示「自定义…」。本轮不做「用户自定义词表」。

**验收**：选「餐饮」出现词表里的词；切「交通」整行换掉；点 chip 备注被填入且可继续编辑；自建分类不显示。

**风险**：低。只影响记一笔面板，`test/ui_shot_test.dart` 的 shot_5 截图需重拍。

## R1 记一笔金额键盘重构（计算器 + 允许 0 / 负数）

**你的原话**：现在的键盘用起来很难受，希望可以简单计算且允许金额为 0、为负。

**现状问题（已核实）**

| 问题 | 代码位置 |
|---|---|
| 只能输入纯数字串，没有任何运算 | `_amountInput` 是 `String`，`Fmt.parseCents` 直接解析 |
| 金额必须大于 0 才能保存 | `record_sheet.dart:82 _canSave => _amountCents > 0` |
| 没有正负号入口 | 键盘只有 0-9、`.`、⌫ |
| 键位命中区曾是死区（已修） | `_key` 已加 `HitTestBehavior.opaque` |

**新布局**：4 列 × 4 行数字区 + 一行全宽「保存」（代替现在右侧的竖条按钮，更好按）

```
 7   8   9   ÷
 4   5   6   ×
 1   2   3   −
 ±   0   .   +
 ⌫   [   保存   ]
```

**输入模型**

| 项 | 规则 |
|---|---|
| 表达式 | `_expr` 字符串，例如 `12+3.5×2`；显示区上行小字显示表达式，下行大字显示实时结果 |
| 运算优先级 | `×` `÷` 优先于 `+` `−`；同级左结合；不做括号 |
| 精度 | 内部用 `double` 计算，**保存时一次性四舍五入到分**（避免每一步取整累积误差） |
| `⌫` | 退一格；长按清空整条表达式 |
| `±` | 给当前输入的数取负（负号只作用于当前数字，不是整条表达式） |
| `保存` | 若有未结算的表达式，先求值再存 |

**0 与负数的语义（待你确认，见下方问题）**

| 方案 | 含义 | 对现有代码的影响 |
|---|---|---|
| **甲：负数＝冲正** | 存负数金额，语义是「反向记账」（如退款 50 元记为支出 −50） | 数学自洽：`monthTotals` 的 `SUM(CASE type)`、账户余额 delta 都会自然相减；列表展示要区分「支出 50」与「冲正 −50」 |
| 乙：负数只是算式中间值 | 保存时取绝对值，并提示「已按正数记录」 | 零改动，但用户会觉得「我输了负数却没生效」 |

**改动点**

| 文件 | 改法 |
|---|---|
| `lib/widgets/amount_keypad.dart`（新） | 从 `record_sheet.dart` 拆出键盘与表达式求值（`CalcExpr.evaluate`），单独可测 |
| `lib/widgets/record_sheet.dart` | `_AmountDisplay` 改为双行（表达式 + 结果）；`_canSave` 放开到 `>= 0`；`_pressKey` 换成表达式模型 |
| `test/calc_expr_test.dart`（新） | 纯函数测试：优先级、左结合、连按运算符、小数点、退格、取负、精度 |

**验收**：输 `12+3.5×2` 显示 19.00 且保存为 1900 分；输 `0` 能保存；`±` 能把 50 变成 −50；`12++` 这类连按不崩、不产生非法表达式；长按 ⌫ 清空。

**风险**：中。键盘是核心录入路径，改动集中在一个面板，`ui_shot_test` 的 shot_5 要重拍；`test/template_test.dart` 走的是数据层，不受影响。

## F4a 全量备份 + 覆盖式恢复


**目标**：一键导出全部数据，换手机/重装能原样恢复。**当前卸载 App 就等于丢光**——`excel_service.dart:24` 的导出只含 `txn` 表，预算、储蓄目标、模板、周期账单、账户余额、分类都不在里面。

**改动点**

| 文件 | 改法 |
|---|---|
| `lib/data/backup_service.dart`（新） | `dumpAll()`：7 张业务表 → JSON（含 `schemaVersion`、导出时间、应用版本）；`restoreAll(json)`：事务内清空后逐表回填，ID 原样保留（外键不变） |
| `lib/data/repo.dart` | 暴露 `dumpTables()` / `restoreTables()`，SQL 仍收敛在 Repo |

**验收**：导出 → 清空 → 恢复 → 逐项比对（账单笔数、月合计、预算、目标、模板、账户余额、多账本数量）。

**风险**：中高。恢复是破坏性写入，必须 ① 二次确认 ② 覆盖前自动备份 ③ 事务包裹，失败整体回滚。

## F4b 智能合并（冲突由用户勾选）

> 你的决定：恢复用**合并**，遇到相同数据让用户选择保留哪些。这条比覆盖复杂得多，所以拆成独立一步。

**先厘清一个关键点**：「完全相同」的记录不需要用户选——直接跳过最省事；真正需要用户决定的是**疑似重复**（同日、同额、同分类，但备注不同）。所以规则分三层：

| 情形 | 判定 | 处理 |
|---|---|---|
| 完全相同 | 指纹相同（date+type+amount+category+account+toAccount+note） | 自动跳过，不打扰 |
| 疑似重复 | 同日 + 同额 + 同分类，备注不同 | **进冲突清单，用户勾选** |
| 全新 | 以上都不匹配 | 直接插入 |

**改动点**

| 文件 | 改法 |
|---|---|
| `lib/data/backup_service.dart` | `fingerprint(Txn)`：对 7 个字段做稳定哈希；合并时按指纹建索引 |
| 新增冲突模型 | `MergeConflict { Txn existing, Txn incoming }` + `MergePlan { insert, skip, conflict }` |
| `lib/pages/merge_review_page.dart`（新） | 冲突清单：一行两组并排（现有 / 待导入），默认勾「保留现有」，可切「用导入的」「两边都留」 |
| 幂等保护 | 导入完成后写入 `last_import_batch` 指纹集合，重复点同一文件不重复插入 |

**验收**：造 3 组数据（完全相同 / 疑似重复 / 全新）各导一次 → 只弹 1 条冲突、相同的跳过、全新的插入；连续导入两次结果不变。

**风险**：高。合并写库不幂等会翻倍脏数据，必须有指纹校验 + 事务 + 二次导入测试。

## F5 发薪日周期归集（已确认要做）

**目标**：把「月」从自然月改成「发薪日周期」。对方整个产品的口径都是这个：明细、统计、预算全按周期归集，「本月」＝上次发薪日到现在。

**为什么必须单独立项**：它不是加页面，是把口径换掉，且要迁移已有数据。

**波及面（已核实）**

| 位置 | 现状 |
|---|---|
| `lib/data/repo.dart` | `monthTotals` / `categoryStats` / `dailyTotals` / `listTxns(month:)` 全部按 `monthStart..monthEnd` |
| `Fmt.monthStart / monthEnd / month` | 全项目 12 处引用，4 个文件 |
| `lib/store.dart` | `month` / `monthIsCurrent` / `loadMonth` / `setMonth` / `shiftMonth` |
| `lib/widgets/common.dart:149 MonthBar` | 文案「2026年10月」要改成区间文案 |
| `budget` 表 | 主键是 `(ledger_id, month, category_id)`，按周期存储要迁移 |
| 筛选面板 | 「本月」档的区间定义随之改变 |
| `test/ui_shot_test.dart` | 多张截图与断言依赖按月口径 |

**需要先定的三个口径问题**

1. **区间归属**：`[本月发薪日, 下月发薪日)` 还是 `[上月发薪日, 本月发薪日)`？—— 决定「今天这笔算哪个周期」。
2. **预算单位**：预算按月给（发薪日只是查看口径）还是按周期存？
3. **发薪日落在 29/30/31**：某月没有这天怎么归（取月末还是提前）？

**设计产出**：`docs/发薪日周期-设计.md`（数据模型、迁移脚本、波及清单、回归范围），先评审再动手。

## 4. 明确不做

| 不做 | 原因 |
|---|---|
| 把 Flutter 换成 WebView | 性能与手感倒退 |
