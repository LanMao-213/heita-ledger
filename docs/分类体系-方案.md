# 分类体系改造方案（定稿版）

> 决策：抛弃「名目」，改为「分类 / 子分类」两级；分类下可挂「详细记录」字段。
> 状态：方案待确认，确认后开工。目标 1.2.0，schema v5 → v6。

---

## 一、定稿分类（支出 9 类 / 50 个子分类）

| 一级 | 子分类 |
|---|---|
| 餐饮 | 正餐、食材、饮品、零食、烟酒、聚餐 |
| 出行 | 公共交通、打车、加油充电、停车过路、共享单车、车辆养护 |
| 居家 | 房租房贷、水电燃气、物业、日用百货、家居家电、维修保洁 |
| 购物 | 服饰鞋包、美妆个护、数码电器、母婴用品、宠物用品 |
| 健康 | 医疗挂号、药品、体检、口腔眼科、健身运动、心理咨询 |
| 娱乐 | 电影演出、旅行度假、游戏充值、会员订阅、休闲玩乐 |
| 人情 | 红包份子、送礼、请客招待、孝敬长辈、公益捐赠、借款 |
| 成长 | 课程培训、书籍、考试报名、知识付费、工具软件 |
| 其他 | 保险、手续费、罚款、代付、不明支出 |

接入方式：沿用 `category.parent_id`，**不新增表、不改 `txn` 主结构**。

四条口径（与上一版一致）：

1. 交易可挂任意一级，挂父级 = 这笔未细分
2. 最多两级，父级本身有 `parent_id` 时禁止再挂子级
3. 预算只设在一级分类
4. 统计按根聚合：`GROUP BY COALESCE(c.parent_id, c.id)`

## 二、两个结构问题（需拍板）

### 1. 借款 / 代付 不是支出

`人情 › 借款`、`其他 › 代付` 本质是**资金往来**，不是消费：

- 借出 5000 记成支出 → 当月支出暴涨 5000，预算被冲垮，月度曲线失真
- 对方还钱记成收入 → 当月收入虚高
- 净额虽然对得上，但「这个月花了多少」这个核心数字错了
- 而且「谁还欠我多少」查不到

三种处理：

| 方案 | 做法 | 代价 |
|---|---|---|
| A（推荐） | 用现有的**转账**类型：建一个「借出」账户，借钱 = 账户间转账 | 零开发；借款不进支出统计；余额可追踪 |
| B | 新增「应收/应付」交易类型 | 要改统计口径、明细页分组、Excel 类型列 |
| C | 保持现状 | 支出统计永久失真 |

A 的成本是用户要理解「转账」这个动作，但现有 App 已经支持转账，只是没人这么用。

### 2. 收入侧分类没有给

用户给的是支出 9 类。收入现在有 7 类（工资 / 奖金 / 提成 / 兼职 / 理财 / 红包 / 其他）。两个选择：

- 沿用现有 7 类平铺（但录入界面是双轮盘，收入侧右轮会空，很怪）
- 同步做子分类，建议 6 类：工资、奖金（年终奖/季度奖/绩效/提成）、兼职（稿费/外包/家教/副业）、理财（利息/分红/基金/股票/房租收入）、红包（压岁钱/过节红包/礼金）、其他（报销/退款/卖二手）

**必须同步做**，否则同一个录入面板有两种行为。

## 三、详细记录字段

### 需求

| 子分类 | 字段 |
|---|---|
| 公共交通、打车、旅行度假 | 出发地、目的地 |
| 红包份子、送礼、请客招待、借款 | 对象 |
| 课程培训、书籍 | 名称（课程名 / 书名） |

### 三种实现路线

| 方案 | 结构 | 优点 | 缺点 |
|---|---|---|---|
| A JSON | `txn.extra TEXT` 存 `{"from":"公司","to":"家"}` | 加 1 列，任意扩展 | 不可索引；Excel 只能拼成一段文字；统计「给张三花了多少」要解析 JSON |
| B 固定列（推荐） | `txn` 加 4 列：`place_from`、`place_to`、`person`、`subject` | 可索引、可统计、Excel 可读；SQLite `ADD COLUMN` 即可 | 语义焊死在列名上，新场景要复用列或再加列 |
| C 属性表 | `txn_attr(txn_id, key, value)` | 无限扩展、可索引 | 所有查询要 JOIN；Excel / 导入 / 备份全部复杂化 |

**推荐 B**。理由：用户提的三种场景正好对应 4 个语义独立的字段，而且「给某个人花过多少钱」是真正能统计出来的，JSON 做不到或做起来极痛。4 列里永远有 2–3 列为空，SQLite 存 NULL 几乎零成本。

### 字段与分类的绑定方式

写死在代码常量里（`lib/data/field_specs.dart`），按「子分类名」匹配：

```dart
const fieldSpecs = {
  '公共交通': [FieldSpec('place_from', '出发地'), FieldSpec('place_to', '目的地')],
  '打车': [ ... ],
  '书籍': [FieldSpec('subject', '书名')],
};
```

**不给 `category` 加配置列，不做字段自定义界面。** 原因：这次只有固定几种场景，用户自建子分类不需要详情字段。将来要放开再加列。

副作用：用户把「书籍」改名成「买书」，字段就失效（和现在 `note_hints` 按分类名匹配的已知行为一致）。

### 后果清单

**得到什么**

1. 记录从「花了多少」变成「花在什么具体的事上」，能查「给张三随了多少礼」「某门课累计多少」
2. Excel 多 4 列可二次分析
3. 低频高额场景（送礼、课程）值得多填两个框

**付出什么（按严重程度排序）**

| # | 后果 | 说明 |
|---|---|---|
| 1 | **录入路径变长** | 记一笔从「金额→分类→确认」变成可能多填 1–2 个框。记账 App 最大的敌人就是麻烦，高频场景（打车每天两次）每次填起终点，用户会在第三天放弃 |
| 2 | **面板高度不稳定** | 切换分类时详情行会动态出现/消失，面板高度跳变。现在的「点备注像重开」问题会**成倍放大**，必须先修好再看这个 |
| 3 | **字段需要额外入口才有价值** | 记了对象名却不做「按对象查看」的入口，这些字段就是死数据。要么本版加一个筛选维度，要么明确接受「只记录不分析」 |
| 4 | **Excel 从 6 列变 10 列** | 导入要按表头名匹配（不能按列索引），老文件缺列要容错 |
| 5 | **备份兼容** | v5 备份没有这 4 列，恢复到 v6 要补 NULL；备份版本号升 v6 |
| 6 | **模板不带详情** | 模板表不加这 4 列，模板只还原分类+金额+备注。否则模板结构跟着膨胀 |

### 建议：分层做，别一次全上

| 优先级 | 场景 | 理由 |
|---|---|---|
| 做 | 人情（对象） | 低频高额，多填一个框不痛；「给谁花了多少」是真需求 |
| 做 | 成长（课程/书名） | 低频，用户明确想要 |
| 缓 | 出行（出发地/目的地） | **高频场景**，每天填起终点会毁掉记账体验；且这些信息事后几乎不查，除非报销 |

如果坚持要做出行，建议：详情区默认折叠，用一个「＋详情」按钮展开，不展开也能保存。

**共同前提：所有详情字段一律选填，绝不阻塞保存。**

## 四、两个体验问题

### 1. 轮盘太小

现状：容器高 192、`itemExtent` 40、字号 15.5 / 14.5、两列 flex 3:4。

调整：

| 项 | 现在 | 改为 |
|---|---|---|
| 容器高 | 192 | 240 |
| itemExtent | 40 | 52 |
| 分隔线高 | 132 | 160 |
| 字体 | 15.5 / 14.5 | 18 / 16.5 |
| 列宽 | 3 : 4 | 4 : 5（子分类名更长，如「停车过路」「日用百货」） |

### 2. 点备注像重新打开

**根因是三件事叠加，不是真的重开：**

1. 焦点进入备注框 → `typingNote = true` → 整块 `CalcKeypad` 被 `if` 移除，面板高度瞬间少约 280dp
2. `AnimatedSize` 用 180ms 收缩，系统键盘弹出约 250ms，两者不同步，中间有几帧「面板已缩、键盘未满」
3. `_onNoteFocusChanged` 里 `_scroll.animateTo(maxScrollExtent)` 在下一帧再滚一次，信息区整体上移

三件事同帧发生（缩高 + 上移 + 内容滚动），视觉上就是关掉一个再开一个。

**修法：**

1. 数字键盘不要 `if` 移除，改为 `SizeTransition` 从 280 → 0 收起，时长与系统键盘对齐（220–250ms，`easeOutCubic`）
2. 去掉 `animateTo(maxScrollExtent)`，改成 `Scrollable.ensureVisible` 只保证备注框可见（避免整块内容上移）
3. `AnimatedPadding` 与 `AnimatedSize` 用同一个时长和曲线，避免「先缩后垫」的错位

预期：面板是「连续让位」，不是「消失再出现」。

**这一项必须在详情字段之前做**，否则动态详情行会叠加新的高度跳变。
